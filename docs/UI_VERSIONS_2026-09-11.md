# v0.4.0 项目版本与工作区改造

日期：2026-09-11。本文是本轮现行功能与交付说明，替代旧报告中的页面入口和项目目录描述；[v0.3 报告](UI_REDESIGN_2026-09-11.md) 与 [v0.2 报告](UI_WORKFLOW_2026-09-11.md) 保留为历史证据。本轮测试和浏览器证据已完成，详细机器记录见 [v0.4.0 验收记录](validation/v0.4.0.json)。

## 参考与本轮目标

本轮实际重启并操作了隔离副本中的 **AnimaLoraStudio 0.27.0**，提交为 `3d9d2e86045b879cd19c01ac4aa2337f45a283ab`。参考使用真实前端和后端、项目接口与配置 Schema；主审查者在浏览器查看了训练参数、数据与遮罩、项目版本、系统环境和模型下载布局。仅关闭参考启动时 TAEFlux 模型与标签词典自动下载，没有下载正式模型或执行参考训练。原参考仓库未修改；本项目根据操作逻辑独立实现，没有复制参考源码。

用户本轮要求不止调整外观：项目、实验版本、训练数据、参数和结果需要清楚关联，顶部硬件读数需要稳定易读，设置需要与训练工作区连贯。实现涉及前端路由和布局、版本数据库迁移、文件副本、目录锁、任务归属与结果查询。

## 工作区布局

- 顶栏顺序为 **CPU → 内存 → GPU → 硬盘**。GPU 内按 **占用 → 显存（MPS 为统一内存）→ 功率 → 温度** 显示四项读数，支持选择监控显卡。缺失值显示 `—`，合法的 `0 W` 不显示为缺失；MPS 的统一内存是系统读数，不等于训练进程分配量。GPU 图标的 ISC 许可随源码和前端产物交付。
- 项目页与训练页共用“项目名称 / 版本名称”、版本栏、版本操作和四步导航。四步为 **训练数据 → 模型准备 → 训练参数 → 任务与结果**，链接携带明确的项目与版本 ID。
- 训练参数继续使用后端 `TrainConfig` Schema。紧凑表单、标签与控件列、章节导航和错误定位采用一致布局；训练、分桶、模型与输出、采样与高级内容继续保留。草稿自动保存，切换版本和创建副本前等待当前保存，预检与启动仍经过真实服务。
- 分桶显示来自后端计划结果；Mask 编辑继续提供笔刷、撤销、重做、保存与 revision 冲突检测，白色学习、黑色忽略，需启用 `dataset.masked_loss`。图片上限仍为 16,777,216 像素、单边 8192。

## 项目版本怎么使用

新项目自动创建 `v1`。版本名称是可编辑标签，实际文件夹使用稳定版本 ID，因此重命名不会移动文件或破坏任务路径。顶部“新版本”提供三种方式：

| 创建方式 | 保留内容 | 新版本初始数据 |
| --- | --- | --- |
| 配置和完整数据副本 | 选中版本的参数、图片、caption、Mask 和显式验证源 | 实际复制为独立文件，可单独编辑 |
| 仅配置，重新准备数据 | 选中版本的训练参数 | 清空训练及验证来源，关闭验证 |
| 默认配置 · 空白版本 | 默认配置及当前环境的注意力默认值 | 不继承来源版本的数据和实验参数 |

三种方式都不会复制旧任务、采样图或权重产物；完整状态恢复路径、适配器热启动路径和旧日志路径也会清空，输出与缓存重新绑定新版本。复制返回准备状态并显示文件进度，完成后才允许编辑。磁盘空间不足、来源变动等失败会保留原版本、展示错误并清理本次正常失败产生的副本；服务异常退出后，未完成版本标为失败，不会被当作已完成版本。

“比较”读取两个版本的参数草稿，显示字段差异和数据/任务/产物数量；它不是图片内容 diff 或训练质量评分。“版本设置”可以改名称、说明并归档/恢复；归档保留文件和历史结果，禁止修改或启动任务。归档当前活动版本时，服务原子地选择另一个可用版本；至少保留一个就绪且未归档的版本。有待运行或运行中任务时不能归档。界面可停留在归档版本查看数据、比较和下载，恢复后重新开放编辑。“文件位置”展示数据、配置、缓存与任务目录，供用户确认实际存放位置。

## 数据导入、复制和编辑保护

浏览器上传与服务器目录导入都将文件放入当前版本的受管理目录。目录导入使用完整文件副本，不使用硬链接；图片旁的 caption、Mask 和其他源目录文件一同保留。导入完成后同步当前版本配置；已有 `validation.sources` 中的来源保持验证用途，原有 repeats、caption 扩展名等未显式修改的参数保留。保存原始来源路径用于去重，并在后续 fork 中继续继承。

版本复制覆盖配置里的训练源、显式验证源及已注册数据集，重写副本路径，再为新数据源建立独立索引。不同版本内的 caption/Mask 编辑不会反向修改已复制的原版本。复制期间，源版本的配置和数据操作受维护锁保护；数据编辑还会检查待运行及运行中任务，索引启动与状态检查使用同一锁。移除数据源同步删除所属版本的训练/验证配置引用和 `datasets/<did>.json` 索引，不删除原始目录或已经导入的图片副本，也不会误改活动的另一个版本。缩略图、图片探测缓存和已编码缓存不会随移除操作自动清理。

## 目录、迁移和任务归属

默认新版本布局如下。自定义缓存/输出根目录时分别使用 `<设置目录>/<项目 ID>/<版本 ID>/`，输出目录下每个任务再使用独立任务目录，编码缓存则在同一版本内共享。

```text
studio_data/
├── studio.db                         项目、版本、数据源、任务与产物归属
├── settings.json                     全局偏好与路径
├── projects/<pid>/
│   └── versions/<vid>/
│       ├── config.json               当前版本可编辑的参数草稿
│       ├── datasets/<did>-<名称>/    图片、caption、Mask 等文件副本
│       ├── cache/                    此版本任务共享的编码缓存
│       │   ├── latents/              VAE 潜变量，按内容哈希分层
│       │   ├── text/                 文本编码，按内容哈希分层
│       │   └── fingerprints/         文件哈希索引
│       └── runs/<jid>/
│           ├── job-config.toml       服务交给工作进程的配置
│           ├── config.toml           训练器记录的运行配置
│           ├── events.jsonl          结构化训练事件
│           ├── run.log
│           ├── samples/              此任务生成的采样图
│           ├── *.safetensors         此任务导出的权重
│           └── state-*/              按保存设置或暂停产生的完整状态
├── datasets/<did>.json                独立数据源索引
├── cache/                            图片探测缓存与无项目任务缓存
└── runs/<jid>/                       无项目任务
```

旧数据库升级时，在事务中补充版本表与归属列，为原有项目建立兼容 `v1`，把原数据源和任务关联到该版本，产物优先沿所属任务归属。**迁移不移动旧文件**，不改旧任务的 `run_dir` 或 `config_json`。旧项目草稿仍读原来的 `projects/<pid>/config.json`；旧缓存、输出与断点继续由历史任务原路径访问。迁移可以重复启动，不应重复创建兼容版本。旧数据不会仅因升级就自动复制成新的受管理目录。

每个新任务保存明确的 `version_id`、配置快照和独立运行目录。切换活动版本后，旧任务的继续训练、重试、采样查询和产物登记仍使用原任务归属。“任务与结果”提供训练任务、采样图和模型产物三个页签；采样图按任务选择和查询，权重带原始任务/版本信息，不按当前版本输出目录里的全部文件猜测归属。

## 设置与真实服务

从侧栏或训练工作区打开设置时，显示右侧宽抽屉，关闭后回到原工作区。直接访问设置 URL 仍可显示独立页。顶部固定四个分类，正文带章节索引：

| 分类 | 内容 |
| --- | --- |
| 运行环境 | Python/Torch 与可选依赖的状态、版本、用途；展开条目后管理安装计划与日志 |
| 模型权重 | 按组件展示候选、路径、状态、默认选择、本地注册及已有下载来源 |
| 存储路径 | 模型、缓存和输出路径；数据根目录展示本次启动值 |
| 界面与服务 | 语言、主题、服务监听等偏好 |

设置中移除训练产物入口，结果在项目版本内查看。旧产物链接转入项目结果流程。模型下载由后端管理，关闭设置抽屉不会取消下载；重新打开会读取真实状态。依赖变更仍需先生成计划、明确应用，Torch/CUDA 等基础运行时继续受保护；变更后需重启，维护门禁不会因为抽屉关闭而解除。本轮不宣称已完成真实 CUDA wheel 安装。

配置导出使用 `__ypuddin_nulls__` 保存 TOML 无法直接表达的空值，导入和训练进程共用解析逻辑，因此关闭按轮采样、按轮验证或按轮保存不会因省略字段而被恢复成默认值。普通旧 TOML 的未配置字段仍使用默认值；已经丢失的旧空值不自动猜测恢复。采样列表按实际文件去重，保留同一步数的步采样和轮采样，任务结束后补齐完整记录。

开发前端默认连接真实后端。只有开发模式下显式指定 `VITE_USE_MOCK=true` 才启动 MSW 与模拟 SSE；模拟曲线、项目和设备信息不能作为训练成功证据。普通 `npm run dev` 不再自动显示演示数据。

## 更新与兼容边界

1. 升级前保留 `studio_data`、自定义输出和外部数据。停止旧服务，更新 Git 源码或解压发布包的源码，再运行 `studio.bat` / `studio.sh`；不要用新目录覆盖自己的数据、环境或权重。
2. 启动器在重启时检查依赖签名与前端内容指纹。已有构建与源码匹配时可不安装 Node；需要重建则要求 Node 20.19+（20.x）或 22.12+。这是启动时增量检查，不是联网程序自更新或生产热更新。
3. `paths.cache_dir` / `paths.output_dir` 影响新任务，不搬迁历史任务。监听地址与端口下次启动生效；数据根目录由 `--data-root` 控制，不由设置页迁移。
4. **版本数据仍可编辑，任务没有单独的不可变图片快照。** 暂停后修改同版本图片、caption 或 Mask，再精确续训会受数据指纹检查约束。需要保留实验数据时，应先建立完整数据副本的新版本再编辑。
5. 高级 TOML/API 仍允许明确引用外部或其他版本的路径；这些直接引用不自动获得独立副本。物理隔离来自上传、目录导入和完整版本复制通道，不能把可编辑配置称为强制文件系统隔离。
6. 完整训练状态继续使用 state v2。数据库版本迁移不会转换旧训练状态指纹，旧状态不得绕过兼容检查；已有适配器权重仍可按热启动方式用于新训练。
