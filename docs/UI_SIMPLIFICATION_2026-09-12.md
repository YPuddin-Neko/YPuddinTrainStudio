# v0.5.1：界面精简、项目目录与正则图

本轮根据实际浏览器批注修改。参考 AnimaLoraStudio 0.27.0 的设置分区、标签查看、正则数据准备流程，独立实现；参考仓库只读，未复制 GPL 实现。

## 界面

- 顶栏 CPU、内存、GPU、硬盘顺序保持不变。正常连接不再分配空的状态槽，硬盘区域末尾到窗口右边缘为 16px；标签与读数保持居中。读取失败仍有可重试反馈。
- 侧栏采用图形标记和两行品牌文字；底部主题、语言两个等宽控件显示当前选择。支持跟随系统/浅色/深色。保存失败保留原选择；版本号仅在“界面与服务 → 服务”中读取实际 API 版本。
- `StudioSelect` 统一菜单、选中态和明暗主题，支持方向键、Home/End、字符查找、Enter、Escape、Tab、禁用项及视窗边界定位。嵌套下拉框/路径弹窗的 Escape 不会把外层设置一并关闭。
- 运行环境保留 Python、PyTorch、计算后端、设备与 xFormers/FlashAttention 加速管理。常规依赖列表和常驻操作历史退出页面；正在执行的安装、需要确认的计划、失败日志仍能查看。旧 Sage 默认值保留并标明仅采样。
- WD14 自动打标、模型下载入口和推理 API 移除。标签步骤改为选图、完整原标签、搜索与分页，保留逐图标签/遮罩编辑入口。既有标签、已下载模型和历史操作备份不删除。
- W&B 不再作为默认安装依赖或前端选项；本地训练日志、曲线继续保留。历史配置可以读取。

## 项目、版本和任务目录

新项目表单要求分别输入显示名称和项目 ID。名称支持多语言；ID 仅允许 1–64 位 ASCII 字母、数字、下划线，拒绝 Windows 保留设备名，按大小写不敏感规则检查重复，不覆盖已有文件夹。旧 API 不传 ID 时仍可生成 ID，以保持兼容。

```text
studio_data/
  project/<project_id>/
    v1/
      config.json
      traindata/<dataset_batch>/
      reg/<regularization_batch>/
      samples/<job_id>/
      output/<job_id>/
      cache/
    v2/
      ...
```

项目显示名称可以修改，项目 ID 和物理目录不随名称变化。版本 API ID 保持全局唯一，独立 `number` 决定 v1/v2 物理目录；复制与创建新版本不会共用可修改的数据文件。每次训练生成独立任务 ID，采样和产物按该 ID 分开。旧项目和旧任务继续读取原来的 `projects/…/versions/…` 与 `run_dir/samples`，不自动移动文件。

存储设置的 `output_mode=project` 是默认模式。`custom` 使用自定义根目录，并追加项目 ID、版本号、任务 ID；训练配置显式指定的输出根也保留。训练产物实际路径由任务返回，采样仍归项目版本的 `samples/<job_id>`。缓存和模型路径仍可单独设置。

## 正则图

数据准备新增“正则图”步骤，提供已有图片导入、本地底模生成、Danbooru/Gelbooru 收集。每次操作独立记录 ID、进度、取消状态和实际新增图片数。

- AI 使用当前版本配置的底模权重和明确填写的类别提示词，不构造训练适配器或优化器；不自动下载模型。逐行提示词轮换，种子逐张递增。推理在独立进程执行，与训练和环境安装互斥。
- 网络收集使用限定站点 API 和媒体域名，固定一般/全年龄评级，下载原图并保存站点标签；无需自动打标。支持排除标签和本次使用的站点凭据，凭据不回显、不写入任务配置或日志。
- 图片解码检查、像素内容去重和标签检查通过后，才把完整批次从临时目录发布到版本 reg 目录并登记 `is_reg=true` 数据源。失败或取消不登记半成品，不覆盖已有批次；源页面、提示词或种子保留在批次 manifest 中。
- 正则数据默认使用独立 CaptionConfig，不继承主体触发词；不进入自动验证集划分。已有显式 caption 配置继续有效。
- 当前损失语义是普通/正则样本混合后按各自权重求均值；图片数量、重复次数和 `prior_weight` 都影响训练，不能把它解释成独立的 `mean(train) + λ mean(reg)`。

## 启动和升级

Windows 使用 `studio.bat`，Linux/macOS 使用 `studio.sh`；共同由 bootstrap 根据平台选择 CUDA、Apple MPS 或 CPU PyTorch。模型加载、常用优化器、本地日志是默认依赖，NVIDIA 主机额外包含 NVML 监控依赖。首次安装和后续补缺均不需要在环境页逐个安装普通包。

增量升级检查源码安装清单、启动器指纹和实际依赖缺失；保留已安装的 Torch/CUDA/Numpy 原生栈，不因驱动检测改变而自动替换。xFormers/FlashAttention 等可选原生扩展仍需匹配当前平台。未执行用户取消的 npm audit。

## 验证边界

最终测试数量、实际文件检查及浏览器截图见 `validation/v0.5.1.json`。旧版报告中的 WD14 验收是历史记录，不能据此认为本版继续提供自动打标。

本机为 macOS/Apple M4；真实 NVIDIA Windows 环境、完整 Anima/Krea 权重的大模型训练与生成仍需要目标机器验收。受控网络响应测试不等于外部图片站点的实时可用性或账号权限验证。
