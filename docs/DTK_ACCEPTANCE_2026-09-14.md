同一新源码再以默认 `loop.deterministic=false` 完成 Anima 单卡连续/恢复对照，也未达到逐位一致：840 个张量不同，最大绝对差 `3.86596e-4`；采样顺序、RNG、调度器一致，优化器、loss 进度和 PNG 不同。实际记录确认确定性关闭、四种 SDP 实现可选。该连续训练的峰值张量分配为 12,408,484,864 字节，数学 SDPA 对照为 16,987,919,360 字节；两者条件和散列分别记录，不据此宣传数学实现改善恢复。

## 运行时 FP8 量化的小矩阵检查

新节点使用实际 `FrozenLinear.from_linear`，将 BF16 的 128×128 合成权重分别转为 `fp8_e4m3` 与 `fp8_e5m2`。两例均通过 GPU 前向、输入梯度反向和有限值检查；原 BF16 权重不变，量化权重作为冻结缓冲区保存，scale 保持正数 FP32。CPU / GPU 搬运及状态序列化往返后，FP8 字节和 scale 保持一致，恢复后的输出一致。

每例权重从 32768 字节变为 16384 字节，另保留 scale；这只是该线性层的权重存储，并不表示模型总显存减半。初次 64 MiB 临时分配上限小于厂商 BLAS 申请的 76 MiB 工作区，前向因此停止。将探针上限调整为 256 MiB 后，两例完成，峰值张量及库分配为 108.144 MiB、缓存预留为 154 MiB；产品的训练限制没有修改。首次诊断和成功结果均保留，探针退出后两卡回到原空闲基线。

实现保留 FP8 权重与 scale，在计算时反量化到输入精度。这个早期小矩阵探针本身不验证原生 FP8 矩阵乘法、现成 FP8 模型或正式模型训练；后续正式 Krea2 的运行时量化单/双卡四组通过情况已在本页顶部单独追加。探针记录为同目录的 `fp8-runtime-probe.json` 与 `fp8-runtime-64mib-limit.json`。
