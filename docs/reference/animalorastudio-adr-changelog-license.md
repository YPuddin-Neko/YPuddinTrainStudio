- `docs/design/block-swap.md` (2026-07-21, implemented): last N of 28 blocks' weights live in **CPU pinned memory**, prefetched on a separate CUDA copy stream via forward pre/post **and backward pre/post hooks** (forward-only hooks were a real bug: 298× gradient error → v0.21.1). Must swap `param.data` in place, never swap module objects (LyCORIS wraps the original Linear; fp8 `weight_scale` is a non-persistent buffer). Measured RTX 5090: 828 MB/block bf16, 30 ms H2D vs 104 ms fwd+bwd, +7% @1024², +2.6% @1536²; fp8 + 28 swapped → training peak 8.4 GB. Pitfalls: host allocator rounds each pinned tensor to 2^n (11.3 GB → 16.6 GB, exceeded Windows WDDM ~50%-RAM cap) → `PinnedPacker` packs into power-of-2 chunks; `torch._C._host_emptyCache()` needed to actually release; `restore_masters()` before fp8 merge. Impl `runtime/training/block_swap.py`, wiring `runtime/training/phases/models.py:70-125`, loaders `families/{anima,krea2}/loader.py`.
- `docs/design/krea2-fp8-inference.md` (2026-07-16): ComfyUI bit-parity for two formats — `fp8_scaled` (E4M3 + per-layer fp32 `weight_scale`, metadata `_quantization_metadata`, `attn.gate/attn.wo` flagged full-precision) and plain fp8 cast; compute `W = W_fp8.to(bf16) * scale`; norms/modulation/embeds (174 tensors) never quantized; LoRA×fp8 = dequant → add fp32 delta → requantize `scale=amax/448` with stochastic rounding seeded `CRC32(layer_name)`. ## 6. Project self-description (README.en.md, project-structure.en.md, studio-pipeline.md, CONTRIBUTING.md)

- Purpose (`README.en.md:5`): "End-to-end pipeline: Booru scraping → curation → tagging → regularization set → training → image-gen testing" for **Anima** (Cosmos DiT, anime) and **Krea 2** (12.9B single-stream MMDiT; "train on Raw, test fast on Turbo").
- Architecture (`docs/architecture/project-structure.en.md:5-47`): `runtime/` (standalone trainer/daemon subprocess; `anima_train.py`, `anima_generate.py`, `anima_daemon.py`, `anima_reg_ai.py`, `train_monitor.py`), `studio/` (FastAPI + React, 4 layers per ADR 0008, `supervisor/` scheduler thread, `workers/`), `modeling/` (per-family model code), `utils/`, `tools/`. Dependency direction "`modeling → utils → runtime → studio → tools`, no reverse imports" — though `runtime/training/families/*/__init__.py:9-13` import `studio.domain.common` for family defaults (documented as the sanctioned exception).
- Training pipeline (`runtime/training/README.md:5-18`): `main()` = `bootstrap → models.run → dataset → text_cache → models.finish → optimizer → resume → loop.run → finalize`, all mutating one `TrainingContext`. 8 plugin registries: adapters (`lycoris` lokr/loha/lora, `ortho`, `tlora`), optimizers (adamw, automagic, came, lion, prodigy, prodigy_plus_schedulefree, soap, soap_sf), schedulers (cosine, cosine_with_restart, cosine_with_warmup), inference_samplers (er_sde, dpmpp_3m_sde), timestep_samplers (baseline, infonoise, krea2_shift), losses (mse, huber), families (anima, krea2). Rule: "shared code must never branch on `if family == …`; query `spec.capabilities`" (`families/README.md`).
- Hardware (`README.en.md:42-48`): NVIDIA only — "AMD / Apple Silicon not supported". Anima: 16 GB+ recommended, 8 GB without block swap, **6 GB-class** with all 28 blocks swapped (~1.9 GB step peak + resident TE, ~11% slower). Krea 2: training 24 GB with official fp8 base, 32 GB bf16; generation fp8 from 16 GB; with block swap training **12 GB** (~10 GB used), generation **8 GB** (~6.3 GB at 1024²), ~4% slower. RAM 16 GB+, 32 GB+ for Krea 2 (26.3 GB single-file load; swapped blocks resident ~11 GB fp8 Krea 2 / ~3.6 GB Anima). Weights: Raw/Turbo bf16 26.3 GB each, fp8 13.1 GB, TE 5.2–8.9 GB.
- Feature claims (`README.en.md:9-25`): fp8 base for training and inference "bit-for-bit aligned with ComfyUI"; PEFT/comfy-key community LoRAs load directly; output `lora_unet_*` drops into ComfyUI; three taggers (WD14, CLTagger, LLM); auto regularization sets; unified queue with pause/resume/scheduling; LoRA evaluation (CLIP/DINO/CCIP/tag recall); three-level VRAM policy; self-update.
