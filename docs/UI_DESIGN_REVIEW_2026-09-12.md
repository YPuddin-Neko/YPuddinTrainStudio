## 2. 中央访问密钥

设置现在包含五类：**运行环境、模型权重、访问密钥、存储路径、界面与服务**。访问密钥页提供四个明确来源：

- Hugging Face：访问令牌。
- ModelScope：访问令牌。
- Danbooru：用户名与 API Key。
- Gelbooru：用户 ID 与 API Key。

保存和清除反馈在对应来源表单内显示；状态读取失败显示在页顶，可单独重试。字段可见标签简短，无障碍名称保留平台名。保存后清空输入框，已保存值不会重新回填。前端不显示服务端错误原文，避免旧服务或代理返回的密钥出现在页面提示中。

`GET /api/credentials` 只返回四来源的 `configured` 布尔值，并设置 `Cache-Control: no-store`。各来源的 PUT/DELETE 共用 `ModelCredentials`；旧 `/api/models/credentials/...` 入口保留兼容。凭据保存在服务数据根的 `secrets.json`，与公开设置、项目配置、下载/正则任务记录分离，使用原子写入。它是本机敏感配置文件，**不是加密保险箱**；更新时保留，源码包和公开诊断不应包含。

正则收集表单不再要求每次填写账号密钥；后台在任务启动时读取对应站点凭据。Danbooru 未配置时可以尝试匿名接口；Gelbooru 要求先配置账号与 API Key。旧 API 调用方仍可显式提交一组完整的一次性凭据覆盖本次任务，不会被自动保存，也不会把残缺输入与已保存值拼接。运行中的任务保留启动时的凭据；清除只影响后续任务。

模型官方请求只携带对应来源令牌，HF-Mirror 使用匿名请求；清除模型令牌会阻止同来源环境变量/CLI 凭据继续回退。跨域重定向不转发认证头；正则媒体请求不携带站点账号密钥。格式错误响应不回传敏感输入或未知字段名。上述行为使用隔离临时存储和假密钥验证，本轮没有保存、清除或导出用户真实凭据。

## 3. 官方推荐目录与完整性校验

新增 `server/model_recommendations.py` 和 `/api/models/recommendations`，与已撤下的 WD14 推荐目录区分。内置候选覆盖 Anima Base 1.0、Preview 3、Qwen3，Krea 2 BF16/FP8 scaled、Qwen3-VL，以及共用的 Qwen Image VAE。HF 与魔搭的仓库、文件和 revision 显式登记；前端切换来源后使用该来源的映射，不假定两平台的仓库或目录永远一致。Toy 是内置测试族，不需要下载权重。

目录元数据于 **2026-09-12** 通过官方 Hugging Face tree API 与 ModelScope repo/files API 核对，包含精确字节数和 SHA-256。可从 [Anima 官方文件目录](https://huggingface.co/circlestone-labs/Anima/tree/main/split_files) 与 [Krea 2 官方文件目录](https://huggingface.co/Comfy-Org/Krea-2/tree/main) 核查候选发布入口。官方目录信息核对不等于已经下载或训练过这些完整权重，也不代替发布方许可证和受限仓库的权限申请。

推荐下载保存到 `<models_dir>/<family>/<kind>/<sha256前12位>/<文件名>`，同一组件在 HF/魔搭间采用同一目标目录。同目录活跃任务互斥，已有目标不覆盖。流式下载检查字节数、SHA-256、safetensors 可读性和组件类型；验证成功后才发布目录并登记，失败/取消清理本次暂存文件。重新下载从头开始，沿用原任务保存的大小和 SHA-256；后续目录修改或删除不能使旧任务重试降级为无校验下载。不完整的旧校验记录会被拒绝重试。

模型列表刷新只做文件名、大小、允许路径及已有校验记录的轻量检查。尚未验证的本地文件是候选，点击“设为默认”时才读取 SHA-256；相同大小但内容损坏的文件会被拒绝，原文件保留。校验结果按大小、mtime、ctime、inode 和设备身份缓存，文件变化后重新校验。已验证的共享 VAE 可以登记给另一模型族并复用相同路径，不必再下载一份。

自定义 safetensors 单文件下载和完整本地编码器目录登记仍保留。自定义文件不自动获得推荐目录的 SHA-256 身份；不要把通用模型注册或自定义下载描述为已验证等同某个官方版本。设置默认组件也不会覆盖已有项目中明确填写的路径。关闭设置抽屉后下载继续由服务运行。

## 4. 工作区、标签与请求隔离

项目/版本身份和工作步骤在页面滚动时保持可达；训练页面把步骤导航与参数分组固定在各自工作区，正文使用可用视口高度。标签查看器将搜索、数据源和分页放在图片列表上方，左右区域分别浏览缩略图与完整 caption，避免每次翻页滚到长标签底部。数据集详情、可视裁剪、模型选择、项目列表、任务和产物页同步调整紧凑布局和窄屏折行。WD14 自动打标没有重新加入，Mask 与已有 caption 编辑保留。

全局队列使用后端 `GET /api/jobs` 的 `group`、`type`、`q`、项目和版本条件及 SQL 分页。`active` 包括运行、暂停处理、取消处理和已暂停任务；`waiting` 包括排队和定时任务；`history` 包括完成、失败和已取消任务。任务行补充项目显示名称、版本名称和编号。这里是已有 train/cache 任务的监控与控制；模型下载和正则准备仍使用各自服务，不冒充训练队列任务。

任务详情从真实任务读取日志、采样与产物。日志接口新增 `tail` 与 `has_more`，读取有字节和行数上限，避免为展示最近日志一次读入整个大文件。版本结果与全局产物列表保留不同查询范围，选择某个版本不会把历史任务重归属到当前活动版本。

辅助 API 与配置草稿分开处理：任务列表、数据集列表、模型库或预设读取失败，会显示对应失败和重试入口，不能伪装为空数据或把默认配置写回真实版本。版本配置读取失败时不挂载可写的模型/数据表单。重试辅助数据保持用户已输入的路径和参数，保存继续携带明确 `version_id`。项目模型草稿也在版本切换时隔离，不让迟到响应覆盖另一版本；全局模型页各辅助资源失败同样独立呈现。

训练参数草稿增加按项目/版本隔离的 sessionStorage 兜底。浏览器 Back 或离开页面后重新进入时，恢复该版本尚未保存的修改；恢复只合并相对原配置发生变化的字段，避免旧草稿覆盖服务端后来更新的其他字段。自动保存、显式保存与离页保存串行执行，旧请求完成不能清除更新的草稿或用较旧参数覆盖较新输入；存储不可用时仍保留现有保存和离页保护。

通用 `Dialog` 直接导入独立 `dialog.css`。冷启动直接进入项目或模型等路由时，弹窗不再依赖先访问其他页面才载入定位/遮罩样式；该修复不改变弹窗提交、关闭和焦点约束。

这些界面改动没有新增数据迁移：新项目继续使用 `project/<project_id>/vN`，旧项目与旧任务路径不移动。版本数据仍可编辑，任务只保存配置快照；完整续训继续依赖实际模型/数据指纹，不保证修改图片后还能精确恢复。

## 6. 升级方式

先停止训练器，再在源码目录更新 Git 或覆盖发布源码，保留服务数据根、`secrets.json`、外部数据/模型和自定义输出。重新运行 `studio.bat` / `studio.sh` 后，启动器才检查依赖安装签名、缺包和前端内容指纹。匹配的预构建页面无需 Node；需要重建时沿用 Node 20.19+（20.x）或 22.12+ 要求。没有运行中的生产热更新，也不会自行联网拉取项目新版本。

原有 HF/ModelScope 凭据继续从同一文件读取，新站点项按需保存；无需重新填写已有令牌。0.5.2 没有升级完整训练状态格式，也不搬动原有项目数据。

启动兼容性依据现有 `tests/unit/test_bootstrap.py` 回归：缺包修复、标记匹配后跳过网络、基础依赖保护，以及前端清单缺失/损坏时判定过期。本轮未另做 Windows 全新安装或旧检出目录完整升级演练；历史升级演练不能当作本版独立实测。
