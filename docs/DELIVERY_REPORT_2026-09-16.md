## 海光训练结果

正式训练验收使用完整模型和 16 组用户原始 PNG/TXT，在同一环境比较连续 8 步与第 4 步保存、退出工作进程后恢复到第 8 步。全部训练权重、优化器、调度器、随机数、数据位置、训练进度和预览图必须完全一致，未放宽误差阈值。这些严格结果要求开启“可复现训练”，使用对应计算策略并保持运行环境、数据和配置一致；没有把默认关闭时的原生低精度路径宣称为逐位确定。

Anima 双卡全参在 `AdamW / lr=1e-5` 的这组短程配方下出现偏白，严格续训通过不代表画质正常。普通重载、原始底模和桥接器互换对照将问题缩小到训练后非桥接器权重。初始权重和数据相同、首步 loss 和梯度范数一致的条件下，全部参数继续训练、仅训练学习率降到 `1e-6` 后，25 步图恢复明显色彩。该诊断另关闭大型保存，不能冒充新一轮续训验收或长期质量保证；原失败审计及更正证据均保留。建议验证 Anima 小数据全参时先以此较低学习率配方（512 分桶、每卡批量 1、累积 1、逐块检查点、数学 SDPA、可复现训练）短测，不直接沿用 LoRA 学习率。

严格续训差异涉及低精度计算，不能归咎于缺少保存优化器或简单设置随机种子。Anima 最小修复保留原生 LoKr，仅调整训练时线性层：输入和权重先舍入为 BF16，矩阵运算使用 FP32，输出回到 BF16；无梯度预览仍走原生前向。SDXL 使用经验证的 FP32 卷积及线性层反向策略。新旧计算策略的完整状态不混用；与调度方式不一致的旧状态也在加载前拒绝，原配置文件保留。

双卡分片确实将参数、梯度和优化器状态分给两张卡；DDP 则每卡保留完整模型、分配不同数据。两种机制有不同用途。Krea2 12.82B 主参数已真实分成两份，每卡保存一半；使用 Adafactor 的该配方可装进两张 64 GiB 卡，不能外推为 AdamW 也同样装得下。没有承诺多卡恰好两倍速度。

## 多卡的使用方式

单任务 DDP/FSDP 当前限 Linux CUDA／DTK；原生 Windows 当前只支持不同任务分别使用显卡，单任务多卡入口由产品禁用。WSL2 路径尚未真机验收，详见 [Windows 验证范围](WINDOWS_READINESS_2026-09-15.md)。

- 两个不同训练任务：各填 1 张卡，分别指定 GPU 0 和 GPU 1。第二个任务不等待第一个结束；另一张空闲卡也可运行“模型测试”。这条调度路径已有此前节点的真实产品 API 验收。
- 一个大模型放进两张卡：选择全量微调、FSDP 显存分片，训练显卡数量填 2，并指定两张卡或使用自动分配。参数、梯度和优化器状态分片。
- LoRA 使用两张卡分摊样本：选择 DDP，每张卡仍需装下完整底模。它不合并两张卡的显存容量。
- 需要本报告的严格续训行为时，启用“可复现训练”，保持数据、配方、卡数及计算策略一致。错误或不同策略的状态会被拒绝，不静默迁移。

## 界面和参数

- 自动保存只在实际修改后反馈状态；显卡菜单显示“自动”，指定卡数与训练显卡数量严格联动。
- 训练方式移到模型系列旁并统一叫 LoRA；全量微调可分别选择主模型和文本编码器，LoRA 文本编码器仍明确标为未实现；圆角切换、SDXL 路径分组、参数键名、侧栏收起对齐、预设位置和重复问号说明均已调整。
- D0 显示科学计数值；旧配置中的非法 0 明确提示恢复默认，不静默改写。
- 增加训练集配平占比，数据分布显示计算中/更新中及失败重试。
- JSON 标签按模型能力检查，Anima 在各标签组内打乱，保留角色信息、自然语言及未知元数据。
- SDXL Min-SNR、v 预测相关损失与可选 Tokenizer 路径已接入实际后端计算；不把 SD1/SD2 专用开关误作 SDXL 必需参数。
- Windows FlashAttention 2 从多个社区发布批次匹配实际环境，不再锁定 v0.9.6。它们是社区预编译包，不是 FlashAttention 官方 Windows 包。
- 已结束的安装记录不反复出现；安装日志自动跟随最新内容，用户往上翻阅时暂停跟随。
