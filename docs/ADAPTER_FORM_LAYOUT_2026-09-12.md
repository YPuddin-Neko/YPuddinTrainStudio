# v0.5.9 适配器参数表单

## 原因与修改

LoKr 的模式下拉框和数字 Rank 原先放在同一个字段里，撑高了所在网格行。其余字段按 schema 顺序自动排列，造成算法下方留白、Alpha 与 Rank 分离，DoRA 开关又采用整块卡片，视觉高度不一致。

共享 SchemaForm 的适配器分组现在按以下关系排列，预设页和项目训练页共用：

- 适配器算法 / 训练目标层。
- LoKr 参数形式 / LoKr 分解因子。
- Rank / Alpha。
- DoRA 等开关使用独立紧凑行；高级参数和规则编辑器随后显示。

分组最多两列，容器宽度不超过 420px 时改为单列；数字输入和下拉框统一为 34px。其他参数分组的列数规则不变。

LoKr 参数形式是界面控制，不增加配置键。后端仍接收数字 `adapter.rank` 或字符串 `full`。Full 隐藏不适用的数字 Rank 和 Alpha，切回低秩恢复本次编辑中的有效 Rank；切到 LoRA / LoHa 时恢复正整数 Rank，避免留下非法的 `full`。Alpha、分解因子、DoRA、目标层及规则不随模式切换被覆盖。加载其他预设会清除临时 Rank 记忆。

## 验证

相关前端交互回归、TypeScript、ESLint 和生产构建的结果，以及 CUA 浏览器对预设页、项目训练页的布局和保存检查，记录在 `docs/validation/v0.5.9.json`。浏览器编辑使用独立 QA 数据根目录，不修改正式项目或预设。

本次修改限于前端表单和版本交付信息，没有重跑后端完整测试或启动模型训练。v0.5.8 的硬件测试是前一版本的记录，不计作本次新增测试；服务更新后另行检查运行版本、静态资源及原有数据是否保留。
