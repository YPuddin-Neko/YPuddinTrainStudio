# Krea2 缓存与内存说明

本文说明 2026-09-13 的实际实现，针对启用图片缓存、使用文本缓存的正常训练。它解释加载顺序，不是显卡容量保证。

**目前是先缓存图片，再缓存文字，用完各自编码器后卸载；不过，Krea2 的 DiT 主模型会提前读到电脑内存。**

## 启动后会发生什么

| 顺序 | 程序在做什么 | 哪些模型还留着？ |
|---|---|---|
| 1 | 把 DiT 主模型的真实权重读到 CPU，暂不上显卡。 | DiT 已占电脑内存。 |
| 2 | 用 VAE 把图片变成较小的数字表示（latent），保存到磁盘。 | 处理缺失缓存时加载 VAE；DiT 仍在电脑内存。 |
| 3 | 图片缓存完成，卸载 VAE。 | 不再为这份 VAE 保留权重引用。 |
| 4 | 用文本编码器处理描述和提示词，保存数字条件，再卸载文本编码器。 | 处理缺失缓存时加载文本编码器；DiT 仍在电脑内存。 |
| 5 | 配置 DiT 的设备放置或分块换出，开始 LoRA / LoKr 训练。 | 需要 DiT、适配器、梯度、优化器状态和计算中间结果。 |
| 6 | 到预览步骤时，按需重新加载 VAE，把生成结果变回图片。 | 预览结束后，图片缓存模式会再次卸载 VAE。 |

如果缓存已经有效存在，会跳过对应编码。我们的 VAE 和文本编码器按需加载，全部命中时可以省掉对应权重的加载。“只构建缓存”也仍会执行第 1 步；Krea2 当前尚未把 DiT 的实际读取推迟到缓存完成后。

关闭图片缓存后，训练时仍需要 VAE 编码，这时不适用表中的缓存后卸载流程。Krea2 的文本模式 `auto` 会选择缓存。

## 三个容易混淆的词

- **缓存结果**：把图片或文字的编码结果写到磁盘，下次可直接读取。它保存的是结果，不是把整个编码器留在显存。我们的缓存使用 `.safetensors` 文件。
- **卸载模型**：去掉程序对编码器权重的引用，没有其他引用后才可回收。原始模型文件和磁盘缓存都还在，需要时可以再加载。
- **搬到 CPU**：从显存搬到电脑内存，模型仍然存在；这是换位置，不是完全释放。

卸载实现还会调用 `empty_cache()`。它只归还 PyTorch 已经闲置的显存空间，不能强行释放仍在使用的模型、张量，也不会清理磁盘缓存。[PyTorch 官方说明](https://docs.pytorch.org/docs/2.14/generated/torch.cuda.memory.empty_cache.html)。

## 为什么缓存时仍可能占很多资源

**电脑内存（CPU RAM）与显卡显存（GPU VRAM）要分开看。** DiT 在 CPU 时会占电脑内存；编码器在显卡上计算时会占显存。读取权重、编码的临时结果也会产生占用。

当前文本缓存默认每批最多处理 **16 条文字**，与训练图片的 batch 分开。训练 batch 改成 1，不代表文字缓存也变成 1。长描述和大文本编码器可能让这一阶段比预期更吃显存。

缓存完成只省掉反复编码的工作。正式训练仍有主模型、梯度、优化器和计算中间结果的开销；小分辨率、激活重算和分块换出影响的是这些不同部分。把图片和文字的缓存顺序对调，不能保证解决所有内存问题。

本地 AnimaLoraStudio 的 Krea2 训练也先做图片缓存，再做文本缓存。它等两种缓存完成、文本编码器释放后，才加载 DiT；但它的这条路径会保留 VAE。两边各阶段保留的模型不同，因此不能只凭缓存顺序推断谁更省显存。
