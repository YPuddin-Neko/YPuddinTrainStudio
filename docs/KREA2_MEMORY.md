# Krea 2 缓存与内存说明

本文说明冻结文本编码器、启用图片缓存和文本缓存时的加载顺序。**程序先缓存图片，再缓存文字；编码器卸载后，才加载 DiT 主模型的真实权重。**

这里的“电脑内存”指 CPU RAM，“显存”指 GPU VRAM。它们要分别留出空间；分块换出会减少显存占用，同时增加电脑内存占用。

与 AnimaLoraStudio、sd-scripts 和 diffusion-pipe 的源码对比见 [训练流程与缓存对比](TRAINING_PARAMETERS.md#4-图片缓存文字缓存与模型卸载)。

## 启动后会发生什么

| 顺序 | 程序在做什么 | 模型占用情况 |
|---|---|---|
| 1 | 检查 DiT 的形状和配置，建立空的模型结构。 | 还没有加载 DiT 权重张量。 |
| 2 | 用 VAE 把缺少缓存的图片转换成 latent，保存到磁盘。 | 按需加载 VAE；DiT 权重仍未加载。 |
| 3 | 图片缓存完成，卸载 VAE。 | 释放这份 VAE 的权重引用，保留磁盘缓存。 |
| 4 | 用文本编码器处理缺少缓存的描述和采样提示词，保存结果，再卸载文本编码器。 | 文本编码器只在需要编码时加载；DiT 权重仍未加载。 |
| 5 | 加载 DiT，安装 LoRA / LoKr，并按配置安排分块换出。 | 两种编码器已卸载，开始为主模型和训练状态分配空间。 |
| 6 | 正式训练。 | 使用主模型、适配器、梯度、优化器状态和计算中间结果。 |
| 7 | 生成训练预览时，按需重新加载 VAE，把生成结果变回图片。 | 预览结束后，图片缓存模式会再次卸载 VAE。 |

已有有效缓存时，会跳过对应的编码工作；如果全部命中，就无需加载相应编码器。“只构建缓存”会停在缓存准备阶段，不会加载 DiT 权重张量。首次校验模型内容指纹时，程序仍可能读取文件计算哈希，这与把整个模型留在内存中是两回事。

冻结文本编码器时，Krea 2 的文本模式 `auto` 选择 `cached`；训练文本编码器时改为在线编码，编码器权重与反向图需留在训练设备上。关闭图片缓存后，训练时还需要 VAE 编码，以上两种情况的训练占用均不同于上表。

## DiT 会先放到哪里

使用 CUDA 和分块换出时，程序会在编码器卸载后，检查当前真正空闲的显存，再选择准备方式：

- **显存足够时**：先把完整 DiT 临时放到显卡，释放 CPU 上的模型文件映射，再把配置要求换出的块放进电脑内存。这样可以错开“读取完整权重”和“建立主机缓存”两次较大的内存占用。
- **显存不足时**：仍按原方式在 CPU 加载，再建立分块换出所需的主机缓存，将常驻部分移到显卡。需要依靠换出才能放下模型的机器，也保留这条路径。

“足够”的条件是：**空闲显存至少能容纳实际权重，再额外留下 2 GiB**。权重大小来自所选文件的头部，并按加载时的精度计算；FP8 权重保持 FP8，缩放值使用 FP32。它不是直接拿文件名、参数量或显卡标称容量来猜。

例如，目前 Raw / Turbo FP8 文件在其余浮点权重使用 BF16 时，模型张量约占 12.239 GiB，因此临时整模上传需要至少约 14.239 GiB 的空闲显存。**这是临时上传权重的门槛，训练峰值还需加上其他组件的占用。** 其他程序的占用、训练和预览的中间结果都会额外占用显存。

这个选择不会改变配置中的换出块数、训练精度、学习率或 batch。CPU 和 MPS 任务保持各自原有路径。日志会记录实际选择、权重预算和当时的 CUDA 空闲显存。临时上传后，分块复制完成会归还已经闲置的 CUDA 缓存；正在使用的张量不会因此被释放。

## 分块换出与 FP8 文件映射

分块换出保存的是冻结的主模型权重。程序在计算需要时把相应块送到显卡，反向传播也使用同一套调度；可训练的适配器和梯度仍留在训练设备上。每个块中相同精度的冻结张量共用一块主机存储，减少逐个分配产生的预留空间，FP8 权重与 FP32 缩放值分别保存。

FP8 文件中的缩放值决定权重在计算时如何还原。程序在权重搬到设备前释放对原文件的引用和临时加载字典，使整份文件的内存映射可以释放；FP8 数值和缩放值保持原样，不会重新量化。

内存映射是一种直接读取文件内容的方式；第一次加载时，进程占用可能还很低，真正遍历、复制权重时才快速上升。因此，既要看准备完成后的占用，也要看搬运过程中的峰值。只降低训练图片分辨率，不能消除由主模型文件和主机缓存造成的占用。

## 缓存、卸载与搬到 CPU

- **缓存结果**：将图片或文字的编码结果写入磁盘，下次直接读取。保存的是结果，不是让整个编码器常驻显存。
- **卸载模型**：去掉程序对编码器权重的引用，没有其他引用后才可回收。原始模型文件和磁盘缓存仍保留，需要时可以重新加载。
- **搬到 CPU**：从显存搬到电脑内存，模型仍然存在，只是换了位置。

卸载时使用的 `empty_cache()` 只归还 PyTorch 已经闲置的显存，不能清除仍在使用的模型，也不会删除磁盘缓存。

文本缓存默认每批最多处理 **16 条文字**，与训练图片的 batch 分开。描述长度和文本编码器大小也会影响缓存阶段的峰值。缓存完成后，训练和预览仍需要各自的计算空间，不能只凭模型文件大小判断是否够用。

规划和队列准入会读取 Krea 权重文件的头部，按真正保留的 FP8 权重、FP32 缩放值及其他权重精度计数；`base_precision = auto` 不会把原生 FP8 文件误当成整模 BF16。换出量按实际最后几个块的冻结张量计算，训练估算仍保留当前计算块、预取块、FP8 反量化临时权重，以及适配器、梯度和优化器所需空间。文本缓存按默认最多 16 条文字及编码器中间结果另算，缓存阶段与训练阶段取较大的估算值。这些数字是规划估算，实际占用以运行时为准。
