## 检查与更新

在源码仓库中运行：

```bash
python scripts/package_source.py --check-git
```

返回成功只表示已跟踪文件通过路径规则检查，不是对文件内任意秘密内容的保证。它是打包前自动检查，也可以在提交前手动运行；未安装自动提交钩子。

`.gitignore` 不会自动解除已有的跟踪关系。如果另一份仓库确实已经跟踪 `studio_data`，先确认其内容属于本机运行数据，再仅移出索引：

```bash
git rm -r --cached -- studio_data
```

这条命令保留该副本中的本地文件；后续提交移出索引的变更不会清除 Git 历史。不要用 `git clean` 或删除目录来代替。自定义 `--data-root` 由打包器按 `studio.db` 标志识别，但 Git 本身不会据此自动忽略；放在仓库内时，仍需给实际路径添加根锚定忽略规则。没有数据库标志的任意素材、导出或备份目录无法仅凭名称可靠推断，也需明确忽略。

本次测试使用临时 Git 仓库，覆盖普通添加忽略、大小写、源码保留、强制跟踪后打包失败、仅移出索引后文件仍保留及自定义数据目录规则。详细数量、日志摘要和实际源码包验收见 `docs/validation/repository-content-2026-09-12.json` 及新包旁的验证文件。
