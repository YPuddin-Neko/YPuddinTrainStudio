# 多卡训练与任务调度

## 训练方式

| 方式 | 参数与数据分布 |
| --- | --- |
| DDP 数据并行 | 每卡保留完整模型，处理不同图片，再合并梯度 |
| FSDP 显存分片 | 参数、梯度和优化器状态分片存储，计算时收集所需参数 |

DDP 不合并显存容量，每张卡仍需容纳完整模型及当前批次。FSDP 可分摊模型与状态占用，但增加跨卡通信。

| 平台 | DDP | FSDP |
| --- | --- | --- |
| Linux CUDA | 支持，使用 NCCL | 支持 |
| Linux DTK | 支持，使用厂商通信实现 | 支持 |
| Windows CUDA | 支持，使用 Gloo | 不支持 |
| MPS / CPU | 不支持 | 不支持 |

## 配置

在“训练循环 → 设备与批量”设置显卡数量和多卡方式，再在启动区选择具体显卡或自动分配。

`dataset.batch_size` 按每卡计算。完整批次的有效批量为 `每卡批大小 × 梯度累积 × 卡数`。多卡配置中的 `gpu_count` 必须与工作进程数一致。

命令行示例：

```bash
python -m torch.distributed.run --standalone --nproc_per_node=2 \
  -m ypuddin.cli train config.toml --device cuda
```

```toml
[loop]
gpu_count = 2
distributed_strategy = "ddp"
grad_accum = 2

[dataset]
batch_size = 1
```

DTK 的 PyTorch 沿用 `cuda` 设备名称。使用 `torchrun` 时由进程本地编号选卡，不固定传入 `cuda:0`。

## DDP 限制

- 不支持分块换出、编译和梯度检查点。
- 多卡不使用 FP16 动态梯度缩放，混合精度选择 BF16 或关闭。
- 支持的模型与训练对象仍受各模型配置限制。

## FSDP 限制

- 至少两张 Linux CUDA 或 DTK 显卡。
- 训练主模型，冻结文本编码器。
- 优化器限 AdamW、Adafactor、SGD；不支持 EMA 和 Kahan 更新补偿。
- 梯度检查点可选逐块或关闭；不支持分块换出和编译。
- LoRA / LoKr 参数为 FP32，底模不使用 FP8，整层丢弃率为 0。
- 全量微调的可训练参数保持 FP32，可使用受支持的混合计算精度。

## 数据与恢复

各卡分配不同的完整批次。批次数不能被卡数整除时，尾部不足一组的批次在该训练轮次略过，下一轮重新打乱；训练计划显示相应数量。批次数少于卡数时不能开始训练。

原生尺寸的同步方式见 [原生分辨率](NATIVE_RESOLUTION.md#多卡与恢复)。缓存由主进程准备后共享，权重与预览由主进程保存。

精确恢复要求相同的卡数、每卡批大小、梯度累积和分布式方式。DDP 与 FSDP 状态不能互换；更换方式时使用已保存权重初始化新任务。

## 多任务调度

训练、缓存和模型测试共用任务队列。不同任务可以使用不同显卡；同一显卡在所属任务进程及子进程退出后释放。多卡任务取得全部所需显卡后才启动。

指定显卡忙碌时，任务等待该显卡。不指定时选择可用设备。队列的显存准入默认按当前可用显存与计划峰值估算判断；关闭估算检查仍不允许同一卡被多个任务同时分配。

安装或更新扩展等环境变更需要重启服务时，队列不再启动新任务，等待中的任务会显示原因，任务队列页顶部提示重启；重启后队列继续。

估算偏高或显存被其他程序占用时，任务会一直等待。可对等待中或已暂停的任务使用“强制开始”：任务排到队列最前，不再做显存估算检查；暂停调度时同样会启动。没有空闲显卡或同时运行数已满时，最早开始运行的任务会保存完整训练状态并暂停，让出显卡，队列里显示它为哪个任务暂停；暂停的任务不会自动继续，需要手动恢复。指定显卡的任务会让占用这些显卡的任务暂停。模型测试不能暂停，强制开始的任务会等待它结束。
