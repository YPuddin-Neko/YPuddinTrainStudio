# 优化器参数与 Automagic 接入 · 2026-09-14

本轮解决三个问题：切换自适应优化器后仍沿用普通学习率；D Coef 等实际需要调整的参数只有手写入口；参数名称没有说明会改变什么。另增加 Automagic v1 的普通训练实现。

本文记录当前实现、与 AnimaLoraStudio 的区别，以及已经完成的检查。它不代表所有优化器、模型和显卡组合都已验收。Windows 同步与实机结果尚待补入。

## 选择优化器后，哪些由系统管理

| 选择 | 系统管理的内容 | 用户仍可调整的内容 |
| --- | --- | --- |
| AdamW 等普通优化器 | 保留常规学习率与调度设置 | 学习率、调度、权重衰减及对应算法参数 |
| Prodigy | 基础学习率系数固定为 1，不叠加手动分组学习率 | D Coef、初始步长估计、平滑系数、预热保护、权重衰减等；仍可使用外部调度 |
| Prodigy Plus Schedule-Free（PPSF） | 基础系数固定为 1；启用权重平均时外部学习率恒定、不预热 | D Coef、停止自适应的步数、分组估计、权重平均、稳定性与状态精度等 |
| Automagic | 从 0.000001 开始，自行调整逐元素学习率，不叠加外部调度 | 步长上下限、每次调整的增量、统计平滑与内部更新限制 |

Prodigy 的“1”是交给优化器的基础系数，不意味着训练时每个权重都按普通优化器学习率 1 更新。作者推荐保留该系数，用 D Coef 调节估计强度；固定输入是本项目防止误用的界面规则，不是说作者代码只接受数值 1。[Prodigy 作者说明](https://github.com/konstmish/prodigy)

PPSF 的 `use_schedulefree` 可以关闭。关闭后不再使用免调度权重平均，外部学习率调度重新生效；这一模式与开启时分别处理，不能只按优化器名称决定是否忽略调度。[PPSF 作者说明](https://github.com/LoganBooker/prodigy-plus-schedule-free)

## 常用参数到底改变什么

| 参数 | 直观作用 |
| --- | --- |
| 自适应步长倍率（D Coef） | 放大或缩小优化器估计的步长。默认 1，调大通常使更新更强。它应有直接可见的输入框。 |
| 初始步长估计（D0） | 自动估计从多大的数值开始。默认 0.000001，通常无需改变。 |
| 停止自适应的步数 | PPSF 在指定更新次数后停止继续估计步长，仍继续训练。0 表示持续估计。 |
| 更新方向平滑（β1） | 在普通 Adam / Prodigy 中，决定更新方向参考多少过去的信息。 |
| 权重平均系数（β1） | 在 Schedule-Free 中，控制训练权重与平均权重的混合；它不是普通优化器的一阶动量。 |
| 步幅估计平滑（β2） | 平滑梯度大小的统计。数值越大，越看重较久的历史，响应变化更慢。 |
| 步长估计平滑（β3） | 平滑 Prodigy 的步长估计；留空时由 β2 自动计算。 |
| 分组估计 | 让不同参数组各自寻找步长。启用分组平均时，使用各组估计的调和平均。 |
| 分解统计 / FP32 分解统计 | 控制优化器统计如何存储，影响占用与数值精度。它们不改变底模文件精度。 |
| 随机舍入 | 写回 bf16 参数时保留小更新的统计效果；FP32 参数不受此选项影响。 |

专用参数按选中的算法提供独立字段；不会把 D Coef、分组估计等实际支持的功能仅留在“添加属性”里。禁用控件用于显示明确的管理规则或不兼容组合，参数说明应解释影响。

PPSF 的 Cautious 与 Grams 不能同时启用；FOCUS 与分解统计、Adam-atan2 不兼容；EPS 留空启用 Adam-atan2 时不能同时启用 StableAdamW。训练器应明确提示冲突，不能让优化器在后台关闭其中一项而界面仍显示开启。

## 与 AnimaLoraStudio 的区别

对照的是本地 AnimaLoraStudio 提交 `3d9d2e8`，不是对它未来版本的判断。

| 项目 | AnimaLoraStudio 的该版本 | 本轮处理 |
| --- | --- | --- |
| Prodigy 学习率 | 固定为 1 | 采用同样的防误用规则，同时检查额外参数、分组学习率等绕过入口 |
| 普通 Prodigy 的调度 | UI 固定为 none | 保留普通 Prodigy 的外部调度能力；作者也支持无调度或余弦调度 |
| D Coef | Prodigy 与 PPSF 均有直接输入字段 | 增加直接字段及用途说明，作为主要调节入口 |
| PPSF 其他专用参数 | 多数标记为高级，提供部分构造参数 | 扩充为有类型和范围检查的独立字段，按算法和用途组织 |
| Prodigy 预热保护、统计修正 | 默认开启 | 当前字段采用作者构造默认值关闭；已有明确配置应保留，不能迁移时覆盖 |
| PPSF 停止估计时机 | 说明建议总步数的 1/4～1/2 | 默认 0。作者当前 v2 说明已不再要求所有训练都按固定比例停止 |
| Automagic | 有 v1；v2 为默认隐藏的实验功能 | 本轮新增 v1 普通 step 实现；v2 尚未接入 |
| SOAP / SOAP-SF | 有相应实现 | 本轮没有接入，不能算作已经支持 |

已有优化器菜单还包括 Adam、SGD、Lion8bit、Adafactor、AdamW Schedule-Free 等，因此支持范围不能只比较选项数量。某个选项需要可选依赖，和该选项已经在所有设备上实际跑通，是两回事。

## Automagic 的实现与占用

本轮实现使用原作者 Automagic v1 的逐元素方向一致性规则：更新方向持续一致时提高对应步长，方向改变时降低步长，并限制在上下限内。矩阵的二阶统计采用分解保存，参数在正常 `optimizer.step()` 阶段更新，可以进入本项目的梯度累积与梯度检查流程。

该实现使用 FP32 学习率状态，不使用上游的 int8 学习率遮罩；低精度可训练参数另有 FP32 主副本。因此它不是上游量化状态版本的逐步数值复刻，也不能直接沿用其他训练器的显存宣传。

- 学习率遮罩相对 int8 多约 **3 字节 / 可训练参数**。
- fp16 / bf16 可训练参数的 FP32 主副本另需约 **4 字节 / 参数**；FP32 参数无需该副本。
- 这些是状态存储的理论差额，不是训练总显存实测。冻结底模、激活、梯度、其他统计以及内存分配开销还需另计。

Automagic v2 把参数更新放进反向传播，在梯度刚产生时就更新并释放梯度。仅增加下拉选项会绕过梯度累积、全局裁剪等训练逻辑，因此本轮不把 v2 标为支持。

实现直接依据原作者 MIT 来源适配；未复制 AnimaLoraStudio 的 GPL 包装代码。[固定来源与许可说明](../ypuddin/optim/NOTICE.md)

## 学习率曲线如何理解

自适应优化器的监控应显示步长估计，而不是一直显示固定的基础系数 1。Automagic 可报告各组逐元素学习率的平均值；Prodigy 可报告当前 `D × 基础系数`；PPSF 按作者提供的 `effective_lr` 计算报告值。

这些是监控使用的自适应步长标量，不等于每个权重实际改动的绝对值，也不能准确重建刚完成那一步所有坐标的更新。统计修正、逐元素归一化、权重平均、衰减，以及记录发生在 step 之前还是之后，都会影响两者的关系。界面应称为“步长估计”，避免把估计当成精确的参数改变量。

## 已完成的独立核查

- 读取并核对实际安装的 **Prodigy 1.1.2、PPSF 2.0.1** 构造函数、有效参数与冲突处理，同时逐项查看 AnimaLoraStudio 的 UI 字段和实际工厂调用。
- 运行 Automagic 公式对照：以 diffusion-pipe 的 MIT 来源实现为参考，仅将学习率遮罩改为无量化 FP32 存储；矩阵、三维张量、向量和标量各运行 20 次随机梯度更新，并包含权重衰减。参数与学习率遮罩逐步对照通过。此检查验证更新公式，不包含原 int8 存储的近似误差。
- 确认 PPSF 的一个真实边界：当前库允许以 β1=0 构造，但更新后切换 eval 会除以零。因此 Schedule-Free 模式需要在参数校验时限制 `0 < β1 < 1`。
- 旧额外参数迁移抽查：D Coef 从旧 args 迁入独立字段，显式非默认冲突会拒绝；完整 Schedule-Free 类路径采用同一校验；未知自定义类的 betas 保留在 args，并确认实际构造收到原值。
- 部分预设做了三组保存往返检查：关闭 SF 的 PPSF 保留余弦调度；开启 SF 的 PPSF 保存恒定调度；未知自定义类保留原始扩展参数。保存后重新读取的有效优化器配置一致，原输入和无关分区未被修改。
- 对 D Coef 和分组学习率中的 NaN / Infinity 做了拒绝检查。
