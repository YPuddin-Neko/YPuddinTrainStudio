## 训练参数与启动

进入项目的“参数与启动”后，配置表单按四个标签组织：

| 标签 | 用途 |
|---|---|
| 训练参数 | 调整训练循环、适配器、优化器等常用参数 |
| 数据与分桶 | 检查训练来源、分辨率、批次和实际分桶结果 |
| 模型与输出 | 设置模型组件与保存配置 |
| 采样与高级 | 配置预览、验证及其他高级功能 |

表单继续以服务端 `TrainConfig` JSON Schema 为依据，使用紧凑字段布局、条件显示、搜索和高级字段切换。预设与 TOML 导入导出保留。检查结果集中显示；点击可定位的问题会切换到对应标签、展开高级字段并聚焦字段，避免用户在长表单中寻找错误。

修改会自动保存草稿。页面内导航会等待最新草稿保存，失败时保留当前页面和错误原因；入队使用当前配置并经过服务端预检。自动保存不是对关闭浏览器、断网等情况的无限保证，应在离开前确认保存状态。

分桶结果来自后端 Plan，随有效配置重新计算。可以先在“数据与分桶”修改分辨率，再核对各桶尺寸、样本和步数；配置不完整时先处理检查项，通过后点击“开始训练”，在任务页查看状态、损失、检查点和下载结果。

## 遮罩编辑与训练生效

从项目数据源进入图片列表，打开图片的遮罩编辑器。编辑器支持真实笔刷、擦除、平移缩放、撤销和重做，并显示覆盖率。**白色区域参与学习，黑色区域忽略，灰色表示部分权重**。保存写入图片旁同名 `.mask.png` 灰度 PNG，不改原图和 caption；重新打开会读取保存后的遮罩。

已有数据会优先读取 sidecar 遮罩，其次读取原图 alpha；两者都没有时默认全图参与。可直接点击“保存并启用遮罩训练”，保存后开启项目的 `dataset.masked_loss` 并返回训练配置；只点击“保存遮罩”时，需要自行在训练参数中启用该选项。遮罩与 latent 缓存分开读取，已有 latent 缓存不会使修改后的遮罩失效，也不需要因此重新做一遍 VAE 编码。

当前手工编辑限制为总像素不超过 **16,777,216**、任一边不超过 **8192**。保存必须与原图训练方向下的尺寸一致。接口使用 revision 检查并发修改，旧编辑页面不能覆盖较新的文件；图片索引中或本项目仍有运行、暂停中、取消中的任务时，保存会被拒绝，需等待相应操作结束。该锁按项目实施，不应把同一外部数据目录同时交给多个项目修改。

这是手工训练遮罩工作流。本轮没有接入参考项目的动漫头部检测模型或自动遮罩任务。

## 环境、模型与存储入口

“设置 → 环境设置”分为三个标签：

| 标签 / 地址 | 内容 |
|---|---|
| 运行环境 `/settings/environment?tab=runtime` | Python、PyTorch、CUDA / MPS、可选计算扩展、操作计划与日志 |
| 模型权重 `/settings/environment?tab=models` | 组件来源、本地注册、下载、默认模型 |
| 训练产物 `/settings/environment?tab=artifacts` | 已保存权重的查看与下载 |

路径、服务监听、语言和主题位于“设置 → 存储与界面” `/settings/preferences`。缓存、模型和输出路径设置用于后续任务，不自动搬迁已有文件；数据根目录由启动参数 `--data-root` 指定。监听地址和端口变更需要重启服务，语言和主题可即时应用。

环境管理的安装、修复或卸载先生成变更计划，安装规划使用 pip `--dry-run --report`，限制为可用 wheel，不自动源码编译。现有 PyTorch、TorchVision、TorchAudio、Triton、NumPy 和 NVIDIA / CUDA 运行时包属于保护范围；涉及替换这些包的计划会被拒绝。页面的“检查兼容性”或上传 wheel 不等于已经安装。

上传 `.whl` 后会检查平台、Python 标签及适用的 Torch / CUDA 构建信息。Windows 上 FlashAttention / SageAttention 需要兼容的预编译 wheel；兼容性无法确认时明确拒绝。核对包名和版本变更后，用户必须点击应用才进入实际修改。运行中的训练或缓存任务会阻止环境修改；应用期间队列受维护状态保护，发生环境修改后必须停止并重新启动 Studio，重启前不启动新任务。实际修改失败也可能需要修复后重启，不承诺自动回滚。

本轮验证了这些接口、规划和保护逻辑及浏览器入口；安装测试中的 pip 与子进程计划使用模拟执行，**没有实际安装或更换 CUDA 扩展 wheel**，当前训练环境没有因该测试被修改。扩展已安装、可导入、通过运行探测是不同状态；没有完成的探测不会被当作训练加速验收。

“新任务默认注意力”用于新的配置草稿；已有项目保存的显式配置保持原值。Anima / Krea 2 共用 xFormers 和 FlashAttention 路径，SageAttention 只在明确的采样上下文使用，梯度训练及检查点重算仍使用 SDPA。

模型权重页按模型族组织 DiT、文本编码器与 VAE，可以登记已有文件、扫描目录或使用组件预填下载来源；下载表单支持 Hugging Face 文件链接及“仓库 + 文件名”，完成后可设置为默认组件。“更改保存目录”跳转至存储设置；已有文件不会因下载而覆盖。

## Windows 获取更新与重启

使用 Git 工作副本时，在已配置远程仓库的源码目录中执行 `git pull` 获取更新；没有 remote 的本地仓库需要先取得新版源码或配置实际更新来源。更新前停止 Studio，保留 `venv`、`studio_data` 和自定义素材、权重、输出目录。获取源码后重新运行同一目录中的 `studio.bat`，再刷新浏览器。

`studio.bat` 调用 `scripts/bootstrap.py`。启动时按 `pyproject.toml`、所选 PyTorch 构建、依赖组和系统平台计算安装签名，变化时尝试更新依赖；签名与解释器文件匹配会直接跳过，不逐项检查已安装环境，也不保证自动修复损坏依赖或切换到正确 CUDA 构建。需要诊断时运行 `studio.bat doctor`。

前端使用源码与构建输出的内容指纹检查。源码变化或输出损坏会触发重新构建，构建需要 Node.js 20.19+（20.x）或 22.12+。如果完整发布包中的预编译前端指纹匹配，则无需 Node；若已有前端与源码不符而没有 Node，会明确报错。只有源码、没有前端和 Node 时，API 能启动也不代表网页可用。

这是**取得更新后重启时的依赖和前端检查**，不是生产服务热更新，也不是联网自动拉取本仓库新版本。环境管理中的可选扩展安装同样不能代替完整的 Python / CUDA 迁移。

- **前端**：115 项测试通过，覆盖 25 个测试文件；最终一轮 lint、TypeScript 与生产构建均通过。
