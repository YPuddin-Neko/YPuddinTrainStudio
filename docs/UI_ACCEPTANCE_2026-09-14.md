本轮修复的是页面显示和操作反馈问题。训练算法、分桶、模型训练范围的内部编号与匹配规则均保持原值。

## 这次修了什么

| 问题 | 修复后的表现 |
| --- | --- |
| 工作台右上角只有白色按钮框 | 主按钮样式不再被队列页面的通用按钮背景覆盖；直接打开、刷新、跨页返回都显示蓝底白字。 |
| 深色模式部分按钮文字不清楚 | 将强调文字颜色与实心按钮底色分开；模型下载、项目创建、数据集、标签编辑和 XYZ 操作使用统一的可读配色。 |
| 滚动预设时，顶部露出已经滚过去的输入框 | 固定工具栏遮住顶部留白；窄窗口下改由固定的分区栏遮住同一区域。 |
| “目标层”与内部编号难理解 | 改为“训练范围”，显示常规、精简、全部线性层等名称；常驻提示建议保留默认，详细说明解释影响，具体层数和匹配规则放在高级说明中。 |
| 选项写着“与其他训练器一致” | 改为当前选项实际训练哪些部分；训练器之间的对比保留在技术报告中。 |
| DoRA 被放进“初始化与正则” | DoRA 归入训练结构；初始化、正则和计算选项分别组织。LoKr Full 仍隐藏不适用的 Rank / Alpha。 |
| 窄窗口下队列筛选框撑出卡片 | 约束网格列和子项最小宽度，队列分区按钮在小容器中换行。 |
| 路径、日志、样本提示词和辅助说明偏暗 | 根据浅深主题使用可读文字色，统一输入提示和“不设置”标签。 |
| 深色图表坐标文字不清楚 | 为画布中的坐标、图例、提示框与缩放条显式提供主题色；切换主题时保留缩放范围和图例选择。 |

“全部线性层”仍是适配器的训练范围，不代表训练底模全部权重；Anima 的文字适配层与 Krea 的文字融合层分别命名。

## 如何检查

使用真实本地服务及现有验收数据，运行生产构建，在 Chrome 中检查浅色和深色主题。主要窗口宽度为 375、768、1080 和 1440 像素；分别检查直接打开页面、刷新和应用内切换，避免只在一种样式加载顺序下通过。

覆盖工作台、项目列表与概览、项目数据各分区、独立数据集、训练参数、参数预设、任务队列、任务详情各分区、设置，以及新建项目、封面裁切、路径选择、模型添加、遮罩编辑等弹窗。

操作检查包含下拉搜索与选择、普通/高级切换、LoRA/LoKr 与 Full 模式切换、滚动吸顶、设置关闭返回、数据集返回、主题切换，以及已有 XYZ 对比的翻页和横向滚动。对比度检查同时看实际截图和最终计算颜色，不把动画过渡帧、禁用控件或允许横向滚动的内容区误报为缺陷。

本轮页面检查拦截数据写入，只放行已核实的只读查询和规划计算；不会因此产生新的训练、下载、标签或遮罩修改。任务列表中正在运行与等待任务为空，所以这两个分区检查的是空状态。实际训练与保存链路的既有验收见 [Windows 验收记录](WINDOWS_ACCEPTANCE_2026-09-14.md) 和 [此前完整验收](FULL_ACCEPTANCE_2026-09-13.md)，不将其混算为本轮重新训练。
