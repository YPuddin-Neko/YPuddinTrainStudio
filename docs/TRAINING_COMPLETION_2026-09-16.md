## Native 多卡的零权重补齐

一个逻辑批次可包含多个尺寸。各卡得到的前向分组数可能不同，程序先取得本轮最大组数，分组少的卡额外运行自己的最小分组，并将其损失权重和样本计数置为零。真实图片的 loss 与梯度按全局实际图片数归一，补齐不增加训练权重。

补齐仍有计算、显存和随机数消耗；不能将它理解为免费空操作。全轮逻辑批次不足以再给每卡各分一个批次时，尾部批次会略过，并在计划中提示。这与卡内零权重补齐是不同的规则。FSDP 每个分组都参与通信，DDP 按累积边界同步；二者均需保持各 rank 的调用次序一致。

几何处理、像素预算、样本归一、尾部策略和缓存边界见 [原生尺寸说明](native-resolution.md)。精确恢复保留相同卡数、每卡批量、累积及数据配置，不能用本轮实现替代改变卡数后的状态迁移。

## 文本编码器适配器真正训练什么

选择“LoRA”训练方式后，“训练主模型”和“训练文本编码器”决定适配器安装到哪些组件，至少选择一项。关闭主模型训练会冻结主模型参数，但仍通过主模型计算梯度传回文本编码器适配器；因此不会省掉整个主模型的前向和反向计算。

| 模型族 | 文本组件 | 组件选择 |
| --- | --- | --- |
| Anima | Qwen 文本编码器 | `text_encoder` |
| Krea2 | 对应模型的文本编码器 | `text_encoder` |
| SDXL | CLIP-L 与 CLIP-G | 当前一个文本训练开关同时选择两套编码器 |
| Klein／FLUX.2 | 对应模型的文本编码器 | `text_encoder`；既有模型变体限制继续有效 |

适配器注入编码器的线性层，词嵌入和语言模型输出头不作为文本适配器目标。编码器底层权重保持冻结，只将适配器参数加入优化器。现有 `lora`、`lokr`、`loha`、`full` 四种适配器算法均有组件接线；这里的 `adapter.algo="full"` 是适配层的完整增量矩阵，与 `training.mode="full"` 的组件全量微调不同。

启用文本编码器训练后，必须每步在线编码。`dataset.text_encoding="auto"` 会解析为在线；显式 `cached` 配置会被拒绝，`memory.offload_text_encoder` 必须关闭。在线指本地运行编码器，不涉及云端服务。单卡适配器路径允许关闭或逐块梯度检查点，暂不支持主模型块换出或其他检查点方式。DDP 仍要求关闭梯度检查点、块换出与编译；**FSDP 仍只支持主模型全参，不支持同时训练文本编码器，也不支持文本适配器分片**。

产物保留主模型与文本组件身份：文本适配器分别使用 `lora_te1`／`lora_te2` 前缀，完整恢复状态也按组件隔离。训练参数、优化器、保存和恢复覆盖所选组件。项目内“模型测试”加载文本适配器后，会按当前权重和适配强度重新编码提示词；切回原模型时恢复原条件，不能复用上一个适配器的文本结果。这说明项目内保存／加载／采样链已接入，不代表每个外部推理软件已验证这些模型族的文本适配器格式。

只加载适配器权重属于继续训练的初始权重，不会恢复优化器或数据位置；需要精确续训时使用完整 state，并保持训练组件选择和参数结构一致。计划已经计入所选文本适配器参数，但在线文本反向的激活显存尚无可靠估算：界面返回未知峰值，不能把缺失估算当成零显存或保证能启动。

对应实现：[组件适配器](../ypuddin/adapters/components.py)、[训练准备](../ypuddin/train/trainer.py)、[能力与限制](../ypuddin/config/training_rules.py)、[模型测试加载](../ypuddin/server/xyz_worker.py)。

## SDXL 的 75／150／225 token

`model.sdxl_max_token_length` 默认 75，可改为 150 或 225。数值不含 BOS／EOS，且是各 tokenizer 的 token 数，不是字符数或词数。超过所选上限的部分截断。

150／225 模式将两套 CLIP 各自的 token 按每块 75 个正文位置编码，每块保留起止位置；再拼接首块 BOS、各块正文位置及末块结束位置。最终序列长度分别为 77、152、227。CLIP-G 的 pooled 条件仍取首块，后续块通过拼接的 token 条件参与交叉注意力。它没有扩大 CLIP 的单块位置编码长度。

训练、文本缓存和预览调用同一路径，在线训练保留两套 CLIP 的完整梯度图。默认 75 保留原编码和缓存身份；150／225 使用独立缓存身份并检查缓存张量形状。切换长度后应重新准备文本缓存，不能把旧长度的完整训练状态视为同一续训配方。更长文本增加编码和交叉注意力的计算及显存开销。

实现与回归：[SDXL 编码器](../ypuddin/models/sdxl/text.py)、[分块测试](../tests/unit/test_sdxl_text_chunks.py)、[训练与预览](../tests/unit/test_sdxl_family.py)。

## Windows 的每任务 Gloo 门禁

原生 Windows DDP 不再仅凭“检测到多张显卡”放行。每个任务在自己的显卡掩码下建立 Gloo 进程组，在加载训练模型和改写旧检查点前，先协商各 rank 的精度能力，再验证实际 CUDA 张量的广播、归约、收集，以及小型 DDP 网络的前向、反向、平均梯度和更新后副本一致性。

探针包括 FP32／FP16／FP64 和整数控制操作；配置需要 BF16 时追加 BF16，任意卡不支持则全部 rank 一致拒绝。探针失败不会回退 CPU，也不会继续加载正式模型。它是每次任务的启动检查，不是一次检测后永久保证成功，更不能代替模型容量、长期稳定性、精确恢复和进程回收验收。

当前本地证据是 macOS 上的 Windows 分支模拟，以及真实双进程 CPU Gloo 协议测试。**本轮没有 Windows GPU 实测；原生 Windows FSDP 仍被明确拒绝，WSL2 双卡也没有新增实测结论。** 与多个单卡任务各占一张显卡的队列并行功能应分别理解。完整操作与范围见 [Windows 验收说明](WINDOWS_READINESS_2026-09-15.md)。
