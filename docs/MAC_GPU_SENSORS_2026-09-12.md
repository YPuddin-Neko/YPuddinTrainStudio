# macOS GPU 功率与温度接入 · v0.5.8

v0.5.7 已接入 Apple GPU 利用率，但功率与温度仍返回空值。本版将此前在本机验证过的 IOReport 与 SMC 采集接入正式硬件统计、顶栏和仪表盘，无需 sudo、额外依赖或特权服务。

## 数据含义

- **估算功率**：读取 IOReport `Energy Model` 中 `GPU Energy` 的累计能耗，以两次整数计数的差值除以实际单调时钟间隔。按通道返回的 J、mJ、uJ 或 nJ 转换单位。全局 GPU 汇总存在时不再加分芯片汇总，GPU SRAM 等子项也不重复计入。这是系统 GPU 在采样区间内的估算平均功率，不是整机输入功率或训练进程独占功率。
- **均温**：读取已知机型对应的 SMC GPU 温度区域，汇总有效读数的平均值。提示同时显示最高温和有效传感器数量；区域数量不代表 GPU 核心数。当前映射包含 M1–M4 的已知键，未识别型号不猜测温度传感器。
- 统一内存和 GPU 利用率的定义沿用上一版。功率、温度、利用率分别处理不可用状态，不互相推算。

接口沿用 `power_w` 和 `temp_c`，并新增可选来源、功率估算标记、实际采样秒数、最高温和温度区域数量。OpenAPI 与前端生成类型同步。界面保留小功率的小数，真实 0 W 显示为 0；正数不足 0.01 W 时显示 `<0.01 W`。

## 采集方式

`apple_sensors.py` 是仅依赖 Python 标准库的只读脚本。SMC 只允许读取命令 9 和 5，并检查返回长度、状态、类型和数据范围，没有修改传感器或风扇的命令。IOReport 样本间隔约 0.25 秒，使用实际时钟间隔计算；计数重置、单位变化、重复汇总、缺失值和非法值均按未知处理。

服务器通过当前 Python 解释器的隔离模式启动短期采集进程，设置两秒超时。原生接口缺失、异常退出或卡住不会使服务进程崩溃。成功和失败均缓存两秒，并发调用共享缓存；失败后不继续显示旧读数。本机实际以普通用户 UID 501 成功读取，未安装 helper 或使用 sudo。

接口是 macOS 私有接口，兼容性按可读取的数据判断。跨平台不会加载这些原生库，CUDA 统计不变。

参考：[Stats 的温度区域型号映射](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift)、[IOReport 能耗与温度聚合路径](https://github.com/exelban/stats/blob/master/Modules/Sensors/readers.swift)。实现由本项目独立编写，未复制第三方实现代码。

## 验证

- 69 项原生采集单元测试、60 项硬件与接口集成定向回归通过，覆盖能耗单位、整数差分、重复计数、计数重置、SMC 结构与键匹配、未知值、隔离子进程超时、缓存过期和实际零值。
- 三个前端测试文件共 26 项通过，ESLint、TypeScript 和生产构建通过。
- 本机标准库独立采集实际返回 13.93 W、均温 82.62°C、最高温 85.38°C、8 个温度区域；进程约 0.27 秒。这些是当时设备既有负载下的读数，没有启动训练或压力测试。
- QA 页面实际显示估算功率 18.1 W、均温 82.6°C，提示包含最高温、8 个传感器与来源。1004×773 窗口下，文档无横向溢出，新增读数各格没有文字溢出。
- 正式 8876 已升级到 0.5.8，浏览器刷新后显示 16.9 W、均温 95.8°C、最高温 98.7°C、8 个传感器。升级前后 194 个业务文件、六张业务表、设置与凭据一致；临时测试服务和标签页已关闭。
- 本轮是定向回归与本机 M4 验证，未重跑全量训练测试，也没有在其他 Mac 型号或 NVIDIA 设备上做硬件实测。未执行 npm audit。

正式服务的数据保留、前端构建指纹和浏览器验收记录见 v0.5.8 验证记录（本地验收记录）。
