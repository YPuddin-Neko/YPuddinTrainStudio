# 存储与备份

## 源码与运行数据

源码目录包含启动脚本、`ypuddin/` 后端、`frontend/` 前端和 `docs/` 文档。平台基础环境默认位于源码目录的 `environment/`，前端构建输出到 `frontend/dist/`。

默认运行数据目录为 `studio_data/`：

```text
studio_data/
├── studio.db
├── settings.json
├── secrets.json
├── project/<项目 ID>/v<N>/
│   ├── config.json
│   ├── traindata/
│   ├── reg/
│   ├── cache/
│   ├── samples/<任务 ID>/
│   └── output/<任务 ID>/
├── models/
├── runs/
├── presets/
├── cache/
├── thumbs/
├── network/
└── environment/
```

| 路径 | 内容 |
| --- | --- |
| `studio.db` | 项目、版本、任务、模型登记与产物记录 |
| `settings.json` | 路径、网络、服务和界面设置 |
| `secrets.json`、`network/` | 模型访问密钥与代理凭据 |
| `project/<项目 ID>/v<N>/` | 当前版本的配置、数据、缓存和训练结果 |
| `traindata/`、`reg/` | 训练图片与正则图片，以及同名标签、遮罩 |
| `models/` | 默认模型下载和扫描位置 |
| `runs/` | 未绑定项目的任务输出 |
| `presets/` | 参数预设 |
| `cache/`、`thumbs/` | 图片索引、共享编码缓存和缩略图 |
| `environment/` | 界面创建的 PyTorch 环境、安装器数据和服务控制文件 |

旧项目可能仍位于 `projects/<项目 ID>/versions/`。更新程序保留旧布局。

## 路径设置

模型、缓存、输出和基础环境目录可在设置中指定。默认项目输出按项目、版本和任务分开存放；自定义输出目录采用相同的层级分隔。

上传及导入图片会创建版本内副本。直接引用外部数据来源时，编辑操作作用于外部文件。

数据目录的更换需要手动迁移：停止服务，将原数据目录完整复制到目标位置，再使用新路径启动。更改设置不自动搬迁模型、项目或已有任务产物。相对路径按服务工作目录解析，跨机器部署宜使用绝对路径。

## 备份

停止服务后备份以下内容：

- `studio.db`、`settings.json` 和凭据文件。
- `project/` 或旧布局 `projects/`，包含图片、标签、遮罩和完整训练状态。
- `presets/`、自定义输出目录及外部引用的数据集。
- 无法重新获取的模型权重。

凭据文件以明文保存，应限制读取权限，并从公开归档中排除。

编码缓存、索引和缩略图可以重建，但重建需要时间。仅保留导出的 LoRA / LoKr 权重无法恢复原任务的优化器、步数和随机状态。删除 Python 环境会导致后续重新安装依赖。

## 默认保存目录

“设置 → 存储路径”可分别设置训练产物、恢复点、采样图和日志的默认根目录。自定义根目录下按项目、版本和任务 ID 分开保存；参数中的自定义路径优先于全局默认值。恢复点和日志目录留空时随训练产物保存，采样图目录留空时使用项目版本的 `samples/`。

修改默认目录只影响之后创建的任务，不移动旧文件。暂停、失败后的恢复与任务日志继续使用任务创建时记录的目录。缓存目录也允许在训练参数中单独指定。

路径参数留空时，“浏览”从该功能的默认目录打开；已填写路径时从所填位置打开。恢复点是包含 `state.json` 的 `state-100`、`state-epoch0002` 或 `state-paused` 等目录，完整续训应选择这个目录。
