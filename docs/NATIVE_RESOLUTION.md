# 原生分辨率

原生模式按每张图的尺寸组织训练，不使用公共宽高比桶。实际训练画布仍需满足模型对齐要求、面积上限和最长边上限。

## 尺寸上限

两个上限同时生效，并包含对齐产生的补边。

| 参数 | 填写方式 |
| --- | --- |
| 图像面积上限 | 默认手动 1024，也可选择自动分辨率优先或自动显存优先。数值为等效正方形边长，1024 对应约 105 万像素 |
| 最长边上限 | 任意一边允许的最大像素长度，默认 4096 |
| 超出尺寸上限时 | 等比缩小到上限内，或报错并停止 |

自动分辨率优先根据实际参与训练的图片计算，包含正则图片，不包含已移出训练或划入验证集的图片。每张图片先按最长边上限、模型对齐和图片适配方式计算画布尺寸，再取最大的画布面积作为上限。这个值是容纳当前训练集所需的最小面积预算；不按平均尺寸缩小大图，也不放大小图，不考虑显存容量。

自动显存优先以上述面积为上限，结合当前训练参数、分批方式及编码、训练、预览各阶段的显存估算，选取预算内最大的面积。多卡按参与设备中显存最小的一张计算，并预留 5% 容量。容量未知、估算不完整或最小尺寸仍超预算时，会提示调整参数。估算不能覆盖其他程序临时占用和所有运行时波动，启动前仍会检查可用显存。

修改数据集、显卡选择或相关参数后，参数页会重新计算；显存优先任务入队时固定面积，继续训练沿用原值。

自定义面积上限为 1024、最长边为 4096 时，2048×2048 图片仍会因面积超限缩小。保留该图片的原始尺寸，可将面积上限设为 2048，最长边保持 4096。

`dataset.native_max_pixels_mode` 可设为 `auto`（分辨率优先）、`auto_vram`（显存优先）或 `custom`（手动，默认）。旧配置未填写时沿用自定义上限。自定义输入为边长，`dataset.native_max_pixels` 保存对应面积。例如输入 2048，对应配置值为 4194304。切换到自动模式会保留自定义值，便于切回。

新建原生训练中，面积上限仅约束单张图片的训练画布。同尺寸图片合批后，总面积可以超过这个值，实际显存需求随批量增加。

## 对齐与适配

Anima、Krea 2、Klein 的对齐单位为 16，SDXL 为 8。以 1001×777 原图、对齐单位 16、预算充足为例：

| 图片适配方式 | 结果 |
| --- | --- |
| 保留完整画面 | 不缩放，补边到 1008×784 |
| 裁切填满 | 不缩放，按所选位置裁到 992×768；默认居中 |

“裁切保留位置”提供九个方向。选择上中会保留顶部、从下方裁掉多余部分；选择右上则保留右侧和顶部。图片与遮罩使用相同位置，翻转在裁切之后进行。修改裁切位置后，下次训练会重建受影响的图像缓存；从完整状态恢复原任务时需保持原设置。

超过尺寸限制时，按“超出尺寸上限时”的选择缩小或报错。完整画面模式可通过补边处理短边小于对齐单位的图片；裁切模式拒绝此类尺寸。

图片与遮罩采用相同的变换。补边仍参与模型前向计算，纯补边区域的训练损失权重为零。

## 批次与计算次数

新建任务使用原生批量策略 v2（`dataset.native_batching_version = 2`）。程序先按最终训练画布的宽和高对全部训练项分组，再按“批大小”拆分每组。组内图片和批次顺序每轮重新打乱；同尺寸样本足够时，一次模型前向与反向处理设定数量的图片。

例如，三种尺寸分别有 9、60、4 个训练项，批大小为 32，实际批量分别是 9、32、28、4，共 4 次模型计算，执行顺序由该轮打乱结果决定。不同尺寸分开计算；不足一批时保留真实尾批，不复制图片补齐。损失与梯度按实际图片数归一化。

参数页的“每轮计算次数”表示每轮按尺寸分组运行模型的次数。梯度累积决定参数更新次数：单卡有 4 批、梯度累积为 3 时，每轮更新 2 次，最后一次使用剩余批次。原生模式不按分辨率列表复制样本，来源重复次数仍生效。VAE 编码批量独立控制编码调用，不改变合批后的模型训练批量。

## 多卡与恢复

v2 的 DDP 将同尺寸批次分配给各卡，保留所有训练项。最后一组中未分到批次的卡只参与零梯度归约，不读取或复制图片，也不增加模型计算次数和样本数。

v2 的 FSDP 要求全局批次数能被卡数整除。不能整除时，计划与启动会报错，可改用 DDP 或单卡训练；系统不会自动降级或丢弃尾批。

精确恢复需要相同的数据、几何模式、卡数、批大小和梯度累积。更换原生、裁切或补边模式后，应创建新训练任务。其他限制见 [多卡训练](MULTI_GPU.md)。

旧原生任务的冻结恢复点继续使用 v1：先随机划分逻辑批次，再在批次内按相同尺寸和总面积拆分计算；DDP／FSDP 保留原来的尾部截断和同步补组。恢复时从冻结配置与状态识别策略，不会把旧任务隐式切换为 v2。需要改用 v2 时，使用导出权重创建新任务；缺少可核对的旧配置或策略不一致时，精确恢复会报错。

公开导出的 JSON／TOML 会省略原生模式不生效的分桶字段及来源分辨率覆盖。带恢复路径的旧配置若未记录批量策略版本，导入、导出和预设合并继续保留该字段缺失，实际恢复时再读取检查点；导出本身不需要访问恢复点。显式填写的版本会保留，和恢复点冲突时拒绝恢复。

v2 的数据身份按原生模式实际生效的设置计算。兼容此前包含无效分桶字段的恢复点时，程序先用检查点哈希核对原训练目录中的 `config.toml`，再验证当前图片、标签、遮罩、来源和有效设置。成功恢复后，原配方按检查点哈希保存在记录目录的 `.resume-recipes/`，以便当前配置更新后仍能选择旧恢复点。请保留原配置、配方归档与恢复点；公开配置文件不替代训练目录中的完整快照。
