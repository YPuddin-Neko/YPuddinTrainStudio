# 原生分辨率

原生模式按每张图的尺寸组织训练，不使用公共宽高比桶。实际训练画布仍需满足模型对齐要求、面积上限和最长边上限。

## 尺寸上限

两个上限同时生效，并包含对齐产生的补边。

| 参数 | 填写方式 |
| --- | --- |
| 图像面积上限 | 填等效正方形边长。1024 对应 1024×1024，约 105 万像素 |
| 最长边上限 | 任意一边允许的最大像素长度，默认 4096 |
| 超限处理 | 等比缩小，或停止并报告超限图片 |

面积上限为 1024、最长边为 4096 时，2048×2048 图片仍会因面积超限缩小。保留该图片的原始尺寸，可将面积上限设为 2048，最长边保持 4096。

页面输入边长，配置中的 `dataset.native_max_pixels` 保存面积。例如输入 2048，对应配置值为 4194304。面积上限同时约束一次计算中图片画布的总像素数，不能作为显存容量上限。

## 对齐与适配

Anima、Krea 2、Klein 的对齐单位为 16，SDXL 为 8。以 1001×777 原图、对齐单位 16、预算充足为例：

| 方式 | 结果 |
| --- | --- |
| 保留完整画面 | 不缩放，补边到 1008×784 |
| 裁切 | 不缩放，从中心裁到 992×768 |

超过尺寸限制时，按超限策略缩小或报错。完整画面模式可通过补边处理短边小于对齐单位的图片；裁切模式拒绝此类尺寸。

图片与遮罩采用相同的变换。补边仍参与模型前向计算，纯补边区域的训练损失权重为零。

## 批次与计算次数

一个逻辑批次可以包含不同尺寸。程序在批次内按相同尺寸与面积预算分组，每组单独计算，再按图片数累积梯度。

例如 `[768×512, 768×512, 512×768]`，面积预算为 786432 时，前两张可共同计算，第三张单独计算；三个样本在平均损失中的权重相同。

参数页的“计算次数”表示尺寸分组的模型运行次数。梯度累积决定参数更新次数，两者不等价。原生模式不按分辨率列表复制样本，来源重复次数仍生效。

## 多卡与恢复

多卡先分配逻辑批次，再在卡内分组。不同卡的分组数不一致时，分组较少的卡补充零权重计算以保持通信次序；该过程增加计算开销，不增加真实样本数。

精确恢复需要相同的数据、几何模式、卡数、每卡批大小和梯度累积。更换原生、裁切或补边模式后，应创建新训练任务。其他限制见 [多卡训练](MULTI_GPU.md)。
