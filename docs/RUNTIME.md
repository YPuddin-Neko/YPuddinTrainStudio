# 运行环境

## 平台环境

各启动入口使用独立的 Python 环境：

| 入口 | 默认环境目录 |
| --- | --- |
| Windows CUDA | `environment/windows-cuda/venv` |
| Linux CUDA | `environment/linux-cuda/venv` |
| Linux DTK | `environment/linux-dtk/venv` |
| Apple MPS | `environment/macos-mps/venv` |
| CPU | `environment/<windows-cpu 或 linux-cpu 或 macos-cpu>/venv` |

平台环境不共用依赖。同一数据目录同时只运行一个服务。切换平台前需停止原服务。

基础环境目录可在“设置 → 存储路径”修改，或通过 `--env-root` 指定。新目录首次启动需要安装依赖，已有环境不会自动移动。`--reinstall` 只重建当前入口的基础环境。

## PyTorch 版本切换

在“设置 → 运行环境 → PyTorch 版本”选择与当前平台匹配的构建：

1. 查看版本和安装计划。
2. 下载并准备新环境。
3. 准备完成后重启服务，切换解释器。

新环境保存在数据目录的 `environment/<平台>/runtimes/`。原环境保留，可通过“恢复原环境并重启”切回。准备阶段会检查依赖、服务导入及设备计算；准备失败时不能切换。

xFormers、FlashAttention、SageAttention、bitsandbytes 等扩展需要与新环境重新匹配。海光基础框架按 [DTK 部署](RUNTIME_DTK.md) 安装。

## 扩展安装

运行环境页按平台列出可安装扩展。安装流程包括构建匹配、文件校验、依赖计划和设备检测。Torch、CUDA、NumPy 等基础运行时受保护；扩展安装不会用其他构建替换它们。

扩展更新后需重启服务。具体后端的版本要求和计算限制见 [注意力后端](ATTENTION.md)。

## 下载源与代理

“软件下载源”控制 Python 依赖和 PyTorch 包的来源。设置保存后供启动器、环境准备和扩展安装使用；命令行显式指定 `--index` 时以命令行为准。自动换源可单独关闭。

模型管理中的 Hugging Face / ModelScope 来源独立设置。推荐权重下载失败后，重试使用当前选中的模型来源。

代理支持沿用启动环境、直接连接和自定义 HTTP / HTTPS 三种方式，保存后对新请求生效。远程部署中，代理地址必须能从训练服务器访问；`127.0.0.1` 指服务器本身。服务首次启动前的依赖安装使用终端代理环境变量。

访问密钥在“设置 → 访问密钥”管理。受限模型仍需先在发布平台取得访问权限。

## 设置生效时机

| 设置 | 生效时机 |
| --- | --- |
| 监听地址、端口、数据目录 | 保存后重启服务 |
| 基础环境目录 | 下次通过启动脚本启动 |
| 启动时打开浏览器 | 下次通过启动脚本启动；`--no-browser` 可临时关闭 |
| 模型目录、下载源、代理 | 保存后供后续扫描、下载或请求使用 |
| 缓存目录、自定义输出目录 | 新建任务使用新路径；已有任务沿用原路径 |

设置页的“重启服务”应用已保存的地址和端口。PyTorch 版本切换过程保留当前连接地址。训练、数据处理或安装任务进行中时，服务拒绝重启并显示阻止原因。

## 硬件监控

NVIDIA 容量和使用情况优先读取驱动信息。Apple 使用统一内存，内存读数与系统内存共享；GPU 利用率反映系统级活动。Apple GPU 功率为采样区间的能耗估算，温度为可用 GPU 区域传感器的汇总。

不可取得的读数显示为未知。监控值包含其他程序的占用，训练任务的内存峰值在任务详情中单独记录。
