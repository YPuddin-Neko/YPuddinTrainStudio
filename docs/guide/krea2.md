# Krea 2

Krea 2 是 12.9B 参数的单流 MMDiT，文本编码器是 Qwen3-VL-4B-Instruct，VAE 与 Anima 相同（Qwen-Image VAE）。训练使用 **Raw** 权重；**Turbo** 是蒸馏模型，只用于出图。

## 权重

| 字段 | 文件 | 说明 |
| --- | --- | --- |
| `model.dit_path` | 官方 `krea2_raw_bf16.safetensors`（约 26 GB），或 Comfy-Org 的 `krea2_fp8_scaled.safetensors`（约 13 GB） | 键名可带或不带 `model.diffusion_model.` 前缀。FP8 文件保留原有的 FP8 权重和缩放值，不重新量化 |
| `model.text_encoder_path` | `Qwen/Qwen3-VL-4B-Instruct` 目录（推荐），或 ComfyUI 单文件 `qwen_3vl_4b*.safetensors`（BF16 或 FP8） | 只加载语言模型部分。单文件时把模型的 `config.json` 放在同一目录；缺少分词器时使用内置的 Qwen3 分词器 |
| `model.vae_path` | `qwen_image_vae.safetensors` | 与 Anima 共用 |

内置预设 `krea2-lokr-default`、`krea2-lora-32` 可作为起点。第一次训练前建议先看训练计划的显存估算，并用 `smoke` 自检（见 [安装与启动](install.md#首次运行自检)）。

## 加载顺序

冻结文本编码器时，Krea 2 使用文字缓存（`dataset.text_encoding = "auto"` 会自动选择）。开启图片缓存后，启动顺序如下：

| 顺序 | 程序在做什么 | 占用 |
| --- | --- | --- |
| 1 | 读取 DiT 的形状和配置，建立空的模型结构 | 还没有加载 DiT 权重 |
| 2 | 用 VAE 把缺少缓存的图片编码成 latent，写入磁盘 | 按需加载 VAE |
| 3 | 图片缓存完成，卸载 VAE | 磁盘缓存保留 |
| 4 | 编码缺少缓存的标签和预览提示词，写入磁盘，卸载文本编码器 | 文本编码器只在编码时加载 |
| 5 | 加载 DiT，注入 LoRA／LoKr，按配置安排分块换出 | 两个编码器都已卸载 |
| 6 | 训练 | 主模型、适配器、梯度、优化器状态和中间结果 |
| 7 | 生成训练预览时按需重新加载 VAE | 预览结束后再次卸载 |

缓存全部命中时不会加载对应的编码器；“只构建缓存”停在第 4 步，不加载 DiT 权重。第一次校验模型文件时仍会读取文件计算指纹。

训练文本编码器时改为每步编码，编码器权重和反向图要留在训练设备上；关闭图片缓存时训练阶段还需要 VAE。这两种情况的占用都比上表高。

## 内存与显存

“电脑内存”指 CPU RAM，“显存”指 GPU VRAM，需要分别留出空间。分块换出会减少显存占用，同时增加电脑内存占用。

使用 CUDA 和分块换出时，程序在编码器卸载后检查实际空闲显存：

- **空闲显存能放下 DiT 实际权重并再留 2 GiB**：先把完整 DiT 临时放到显卡，释放文件映射，再把要换出的块放进电脑内存。这样错开“读取完整权重”和“建立换出缓存”两次内存高峰。
- **显存不够**：在 CPU 加载，再建立换出缓存，把常驻部分移到显卡。

权重大小按所选文件的实际精度计算：FP8 权重保持 FP8，缩放值按 FP32。以 FP8 文件为例，模型张量约 12.24 GiB，临时整模上传需要约 14.24 GiB 空闲显存；训练峰值还要加上适配器、梯度、优化器和中间结果。这个选择不会改变换出块数、精度、学习率或批大小，日志会记录实际选择。

其他要点：

- 分块换出保存的是冻结的主模型权重，计算到哪块就把哪块送上显卡；适配器和梯度始终留在训练设备上。
- FP8 文件在权重搬到设备前释放文件引用，让整份文件映射可以回收；FP8 数值和缩放值保持原样。
- 内存映射在刚加载时占用很低，真正复制权重时才快速上升，所以要同时看准备完成后的占用和搬运时的峰值。只降低训练分辨率不能消除主模型文件和换出缓存带来的占用。
- 文字缓存每批最多编码 16 条文字，与训练批大小无关。
- 训练计划按 FP8 权重、FP32 缩放值和实际换出的块估算显存；`base_precision = auto` 不会把 FP8 文件误算成整模 BF16。

三个容易混淆的说法：

- **缓存**：把编码结果写到磁盘，下次直接读取，不是让编码器常驻显存。
- **卸载**：去掉程序对模型权重的引用，模型文件和磁盘缓存都还在，需要时可以重新加载。
- **搬到 CPU**：模型从显存移到电脑内存，模型仍然存在。

## Turbo 用于出图

Turbo 可以登记到模型库，但程序会拒绝用它开始训练，它也不能设为训练默认模型。在模型管理中下载标有“仅采样”的 Turbo，然后在 [模型测试](xyz-sampling.md) 中把它选为采样底模，搭配 Raw 训练出的 LoRA／LoKr。

默认参数：

- 8 步、Euler；CFG 为 0 时只计算正向提示词。
- 固定 `mu = 1.15`，相当于界面里的 Flow Shift 约 3.158。两者是不同的表示方式，不能直接互换。
- 手动设置的步数、CFG 和 Shift 优先。Turbo 的 CFG 采用官方的 `正向 + CFG × (正向 − 负向)`；Raw 保持原有的 CFG 和分辨率偏移。

默认值依据 [Krea 官方模型说明](https://huggingface.co/krea/Krea-2-Turbo) 和 [官方采样代码](https://github.com/krea-ai/krea-2/blob/main/sampling.py)。

推荐下载列表中的 Turbo 文件固定版本、大小和 SHA-256，下载并校验后才登记：

| 条目 | 文件大小 | 说明 |
| --- | ---: | --- |
| `krea2-turbo-fp8` | 13,141,730,784 字节 | FP8 scaled |
| `krea2-turbo-bf16` | 26,283,332,608 字节 | BF16 |

来源为 [Comfy-Org/Krea-2 固定版本目录](https://huggingface.co/Comfy-Org/Krea-2/tree/e5ea8b4dd7f38f348b138eb0fe29f92c0e367e96/diffusion_models)。

## Raw 和 Turbo 的识别

Raw 和 Turbo 的权重结构相同，文件名也可以随意修改，程序不靠文件名或形状猜版本。推荐文件校验完成后，会在旁边写一个小的 `.ypuddin.json` 记录，绑定文件大小、修改时间和文件身份；文件被修改或重新复制后需要重新校验或手动选择版本。未校验的本地模型或自定义下载，登记时按发布说明选择 Raw 或 Turbo。旧训练配置默认按 Raw 处理，无法确认时会报错。
