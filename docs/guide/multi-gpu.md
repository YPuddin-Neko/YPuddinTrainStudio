# 多卡训练

一个训练任务可以同时使用多张显卡，有两种方式：

| 方式 | 做法 | 适合 |
| --- | --- | --- |
| 数据并行（DDP） | 每张卡保留完整模型，各卡处理不同图片，合并梯度后一起更新 | 单卡放得下模型，想用更多卡加快训练 |
| 显存分片（FSDP2） | 主模型参数、梯度和优化器状态分到各卡，计算某一层时临时收集该层参数 | 单卡放不下的训练，例如 Krea 2 主模型全量微调 |

两张 64 GiB 显卡用 DDP 不会变成一张 128 GiB 显卡：每张卡仍要放下完整模型、优化器和当前批次。FSDP 才会把占用分摊到各卡，但跨卡通信会增加耗时，两张卡不一定达到两倍速度。

## 平台

| 平台 | DDP | FSDP |
| --- | --- | --- |
| Linux CUDA | 支持（NCCL） | 支持 |
| Linux 海光 DTK | 支持（厂商 NCCL 兼容接口） | 支持 |
| Windows CUDA | 支持（Gloo，启动前在所选显卡上检查通信） | 不支持 |
| macOS MPS、CPU | 不支持 | 不支持 |

## 在界面中使用

1. 在 **训练循环 → 设备与批量** 设置“训练显卡数量”，再选择“多卡训练方式”。
2. 在启动区的“训练显卡”中勾选具体显卡，或保持自动选择空闲显卡。
3. 启动前查看训练计划中的每卡显存估算。多卡任务要等所需显卡全部空闲才会启动，不会先占一部分卡等待其余的卡。

`dataset.batch_size` 始终是每张卡一次处理的图片数。完整批次下，一次更新覆盖的图片数为：

```text
每卡批大小 × 梯度累积 × 显卡数量
```

例如每卡批大小 1、梯度累积 2、两张卡，一次更新覆盖 4 张图片。

## 用命令行启动

在已准备好的计算环境中用 `torchrun` 启动，卡号由 `LOCAL_RANK` 决定，不要传 `cuda:0`：

```bash
python -m torch.distributed.run --standalone --nproc_per_node=2 \
  -m ypuddin.cli train config.toml --device cuda
```

```toml
[loop]
gpu_count = 2
distributed_strategy = "ddp"   # 或 "fsdp"
grad_accum = 2

[dataset]
batch_size = 1
```

配置里的 `gpu_count` 大于 1 时必须与 `torchrun` 的进程数一致；普通单进程训练遇到多卡配置会报错。海光 DTK 同样使用 `--device cuda`。

## 数据如何分配

- 每轮先生成相同的分桶顺序，再把完整批次分给各卡，各卡不会重复训练同一个训练项。
- 批次总数不能被卡数整除时，最后不足一组的批次本轮略过，下一轮重新打乱；计划会显示首轮略过的训练项数。批次数少于卡数时拒绝开始。
- 原生尺寸模式下，各卡在卡内按尺寸分组计算。分组数少的卡会补跑损失为零的分组，让各卡同步前向和反向；补跑不增加图片权重，只多占一些计算时间。详见 [原生尺寸训练](native-resolution.md)。
- 缓存由第一张卡先准备，其他卡复用，不会同时写同一份缓存。
- 只有主进程写事件、权重、断点和预览图；暂停、停止和手动保存在优化器更新之间同步执行。

## DDP 的限制

- 不支持块换出、编译和梯度检查点。
- 支持分桶和原生尺寸模式下的 LoRA／LoKr，以及主模型、文本编码器或两者一起的全量微调。
- FP16 动态梯度缩放只能单卡使用；多卡请把混合精度设为 BF16 或关闭。

## FSDP 的限制

共同要求：

- 至少两张 Linux CUDA 或海光 DTK 显卡。
- 必须训练主模型，文本编码器保持冻结。
- 优化器可选 AdamW、Adafactor 或 SGD；不支持 EMA 和低精度更新补偿（Kahan）。
- 梯度检查点可选逐块或关闭；不支持块换出和编译。

主模型全量微调：

- 可训练参数保持 FP32，计算时使用混合精度。
- Krea 2 全参训练建议用 Adafactor：它默认不保存一阶动量，优化器状态最小；在优化器选项里设置 `beta1` 或改用 AdamW 会明显增加显存。
- 训练结果保存为 `.model` 目录，与单卡全量微调相同。

LoRA／LoKr：

- 底模可用 BF16、FP16 或 FP32，不支持 FP8；适配器参数必须为 FP32。
- 整层丢弃率（`adapter.module_dropout`）必须为 0，普通 Dropout 和 Rank Dropout 仍可使用。
- 导出的是普通适配器文件，单卡加载和合并方式不变。

## 断点续训

- 精确续训要求相同的显卡数量、每卡批大小、梯度累积和训练方式；DDP 与 FSDP 的训练状态不能互相替换。
- 想换卡数或换方式，从已保存的权重开始新训练。
- 断点记录每个进程各自的随机状态和已训练的批次，恢复后不会重复或跳过数据。
