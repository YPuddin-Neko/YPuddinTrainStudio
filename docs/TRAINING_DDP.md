# DDP 数据并行训练

多卡任务使用 PyTorch DDP：每张卡保留一份模型，各卡处理不同图片，再合并梯度一起更新。两张 64 GiB 显卡不会变成一张 128 GiB 显卡；每份模型、优化器和当前批次仍需放进单卡显存。

## 配置与启动

`loop.gpu_count` 是本次任务使用的卡数，默认为 `1`。服务会为多卡任务保留相应数量的空闲设备，并启动 `torchrun`。单独运行 CLI 时，需在已准备好的独立计算环境中执行：

```bash
python -m torch.distributed.run --standalone --nproc_per_node=2 \
  -m ypuddin.cli train config.toml --device cuda
```

```toml
[loop]
gpu_count = 2
grad_accum = 2

[dataset]
batch_size = 1
```

这里一次更新通常覆盖 `1 × 2 × 2 = 4` 张图片。`batch_size` 始终是每张卡同时处理的图片数。尾批按实际图片数计算，不让只有一张图片的小批次获得与完整大批次一样的权重。

`--device cuda` 使用 PyTorch 的 GPU 接口；海光 DTK 也通过供应商实现的该接口和 NCCL 兼容通信后端运行。程序会检查当前构建是否支持通信，不会自动退回单卡或 CPU。卡号由 `LOCAL_RANK` 决定，不要给上述命令传入 `cuda:0`。

配置未写 `gpu_count` 时，以 `torchrun` 的进程数为准。配置指定大于 1 的数量后，必须与 `torchrun` 一致。普通单进程训练遇到多卡配置会报错，防止界面选择两卡、实际只使用一卡。

## 数据与保存

- 每轮先生成相同的确定性分桶顺序，再把完整批次分给各卡。一个批次中的图片仍保持相同尺寸，各卡不会重复训练同一个训练项。
- 如果批次总数不足以平均分配，最后不足一组的批次略过，下一轮重新打乱。计划和训练事件会显示首轮略过的训练项数量；分桶批次少于卡数时直接拒绝开始。
- 缓存准备依次执行：第一张卡填充共享缓存，后续卡复用缓存，避免同时写索引、指纹和同名缓存文件。
- 只有主进程写事件、权重、断点和采样图。其他进程在保存或预览期间等待，不重复生成产物。
- 暂停、停止和手动保存请求在优化器更新边界同步，各进程不会各自继续训练。
- 断点保存全部可训练权重、优化器状态和每个进程各自的随机状态。精确续训要求相同卡数、每卡批量和梯度累积；更换卡数请从权重开始新任务。
- 分桶断点记录已经实际消费的批次，不把数据预取当作训练进度。每个进程还保存当前轮次创建数据读取进程时的种子，恢复同一轮次不会重复推进随机状态；翻转和标签增广由种子、轮次和样本索引决定，不受数据读取进程的调度影响。

## 当前支持范围

DDP 支持分桶与原生尺寸模式下的 LoRA/LoKr，以及各模型族的全量主模型、文本编码器和两者联合微调。原生模式按尺寸分组，详见 [原生尺寸训练](native-resolution.md)。暂不支持块换出、编译和梯度检查点，配置和计划会拒绝这些组合。各模型族、优化器和计算后端的其他兼容要求不变。
