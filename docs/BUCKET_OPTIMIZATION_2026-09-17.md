# 分桶优化与对照结果（2026-09-17）

本次基于 AnimaLoraStudio 的面积范围网格思路，补齐我们的候选尺寸，并进一步按照图片实际裁切、补边和缩放情况选择桶。已经实现并做本地几何及训练回归；以下数字不代表最终生成画质评分，也不是四个训练器的 GPU 性能比赛。

## 实际修改

1. **完整生成合法桶。** 旧版每个宽度只检查附近三个高度，默认漏掉 4 个合法尺寸，还造成横竖候选不对称。现在枚举整个合法范围，默认 1024、步长 64、面积 ±10%、宽高比上限 2 时，从 33 个补齐到 37 个，与本次 ALS 快照一致。实现按每个宽度的合法高度区间遍历，避免扫描整个方形网格。
2. **按实际像素处理选桶。** 裁切模式优先最少裁切，完整画面模式优先最少补边；使用图片读取和遮罩同一套整数尺寸算法。效果相同时先减少缩小，再减少放大，最后比较目标面积。横竖旋转的选择保持对称。
3. **小图先调整再选择。** 开启“不放大小图”后，对所有候选先缩小、按模型要求对齐，再比较结果；不再先选一个桶，变形后仍沿用旧选择。短边不足模型对齐要求时，裁切填满与不放大不能同时满足，会提示使用完整画面模式。
4. **接入实际数据链路。** 训练、缓存检查和数据分布预览共用数据布局，不另写一份前端分桶算法。来源单独设置的分辨率也参与相同规则。前端参数说明及生成的 schema 已同步。

相同构图时的细节例子：基准 1536 的合法方桶有 1472、1536、1600。ALS 优先靠近基准面积；新版遇到 1600×1600 原图会直接使用 1600×1600，避免缩成 1536×1536（像素数减少 7.84%）。遇到 1472×1472 原图则保持 1472，不额外放大。这里保留的是采样分辨率，不意味着已有训练画质的定量结论。

## 几何实测

全部使用基准 1024、步长 64、面积 ±10%、比例上限 2。裁切占比指缩放后被裁掉的像素面积比例；补边占比指画布中补边的比例。两者不能当成细节损失率或生成质量分数。

### 用户提供的 101 张图

46 张 1448×2656，55 张 2656×1448，只有两种尺寸。新版与旧版都使用两个桶，全部需要缩小；裁切模式平均裁切约 **0.071%**，完整画面模式补边 **0%**。本组图片旧桶已经贴合，因此新版持平，没有人为制造提升。

ALS 在这组图上记录的裁切为 0%，因为其缩放尺寸用 `int` 向下取整，我们使用 `round` 后多出一行再裁切。这是整数重采样差异，不能把这一像素差异直接说成某方训练质量更高。原生模式不参与这张表。

### 3002 组横竖尺寸扫描

构造 500×1000 至 2000×1000、宽度每次增加 1 像素，再加入全部横竖互换尺寸，共 3002 组。它覆盖宽高比范围，但不是 3002 张真实图片，也不代表所有数据集的分布。

| 路径 | 旧版平均占比 | 新版平均占比 | 改善 / 持平 / 变差 |
|---|---:|---:|---:|
| 裁切，允许放大 | 1.3095% | 1.1654% | 230 / 2772 / 0 |
| 裁切，不放大 | 1.3569% | 1.1982% | 320 / 2682 / 0 |
| 补边，允许放大 | 1.3105% | 1.1665% | 229 / 2773 / 0 |
| 补边，不放大 | 1.3547% | 1.1962% | 315 / 2687 / 0 |

允许放大时，最坏裁切从 **4.2177% 降至 2.9384%**；最坏补边从 **4.2614% 降至 2.9412%**。具体例子 522×1000：旧桶 704×1408，裁掉约 4.22%；新桶 768×1472，裁切为 0%。完整画面模式仍有约 0.068% 补边，不能把裁切模式的零裁切说成两种模式都无额外像素。

ALS 的原始选择与原始取整在这组扫描中平均裁切 1.1187%。把 ALS 的桶选择接到我们相同的缩放取整函数，平均为 1.1657%，最坏为 3.0303%；新版分别为 1.1654%、2.9384%。这说明默认配置下，**相对 ALS 的额外平均改善很小，主要收益来自修复我们原先漏桶，以及小图、横竖一致性和同构图缩放策略**；不能宣称全面超越 ALS。

完整指标见 JSON 记录（本地验收记录）。仅读取用户图片尺寸和 EXIF 方向，没有修改图片，记录不包含图片、标签或原始文件名。

## 成本与兼容

候选更多可能把图片分到更多批次，并增加小尾批。此次扫描允许放大时实际使用的尺寸从 33 个变为 37 个，不放大时从 134 个变为 145 个。计算批次利用率、缓存数量或 GPU 用时不保证改善。减少缩小时也可能使用面积范围内更大的桶；例如 1536 基准选择 1600 方桶，画布比基准大约 8.51%，仍在用户允许范围内。

分桶选择在规划时完成，没有给每步训练增加一遍候选搜索。记录中的选择耗时包括指标收集，是本机 CPU 结果，不是训练吞吐。新版只在合法候选范围内按明确优先级选优，不做全数据集聚类、语义主体裁切或 NaViT 打包。

极粗步长或极窄面积范围没有任何合法桶时，保留历史对齐方桶回退；这时可能超出面积范围。“不放大小图”缩小桶后也不再要求满足原始面积下限，向下对齐还可能使很小图片的实际桶比例偏离原候选网格的比例上限。原生模式的尺寸规划和有效画面处理未改动，仍受像素预算限制。

**旧完整状态不能直接使用新桶策略做严格续训。** 归组及顺序可能变化，新增 `complete-grid-pixel-fit-v2` 策略身份校验，会明确拒绝旧桶状态。请用原版本完成旧训练，或从导出的模型/适配器权重开始新任务。同几何的旧图片缓存仍可复用；原生模式不增加这一桶策略身份。
