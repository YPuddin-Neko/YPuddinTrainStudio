# 原生分辨率训练

在「训练参数 → 数据与分桶」将分辨率模式切换为「原生分辨率」。每张图保留自己的尺寸，不再映射到一组公共宽高比桶；小图不会被放大。图片仍需满足模型的尺寸对齐要求，当前模型为 16 像素。

例如，1001 × 777 的图片在预算允许时以 992 × 768 训练：仅中心裁掉对齐所需的边缘，不重新缩放。超过预算的图片默认等比缩小后做对齐裁剪，也可以选择直接报错，先回到数据页处理。图像、alpha 和独立 `.mask.png` 使用相同几何变换。

## 设置和计划

| 设置 | 行为 |
| --- | --- |
| 像素预算 | 同时前向计算的图片总像素上限；默认 1,048,576。单张超限时按溢出策略处理。 |
| 最长边 | 单张训练尺寸的边长上限；默认 4,096 像素。 |
| 超限处理 | 等比缩小，或明确报错；不会静默丢弃图片。 |
| 每批图片数 | 一次逻辑批次的图片数，可以包含不同尺寸。 |
| 梯度累积 | 累积多个逻辑批次后更新；尾批按实际图片数归一化。 |

原生模式不使用公共分辨率列表、宽高比桶、桶步长或多分辨率复制。数据源的重复次数仍然生效。计划面板显示对齐后的尺寸分布、缩小图片数、逻辑批次数以及实际前向分组数。相同尺寸也可能因像素预算而分成多组。

一个逻辑批次为 `[768×512, 768×512, 512×768]`、预算为 786,432 时，前两张可以一起计算，第三张单独计算。三个样本对梯度各贡献三分之一；不会因第三张独占一组而得到额外权重。每个分组完成反向传播后释放其计算图。

## 与参考实现的关系

设计时核对了本地 AnimaLoraStudio 0.27.0 的原生分辨率说明和训练调用链，也参考了 [NaViT 论文](https://arxiv.org/abs/2307.06304) 对不同尺寸训练的讨论。本实现是独立编写的异形逻辑批次调度，使用现有模型前向与损失接口；没有复制参考项目代码，也没有实现 NaViT 序列打包或专用变长注意力内核。

因此不额外依赖 xFormers/Flash Attention，不强制预缓存 latent。现有 Masked Loss、在线 VAE 编码、缓存、暂停和恢复路径都可使用；模型本身的限制依然有效，例如 Krea2 当前的文本缓存要求。按实际图片数计算梯度，末尾不会重复图片来凑齐批次。

## 验证与边界

覆盖测试包括随机尺寸的预算/对齐约束、样本覆盖、确定性恢复、尾批梯度权重、EXIF 方向、图像与 Mask 对齐、缓存变换隔离，以及 Toy 和小型真实 Anima/Krea2 架构的训练/采样/恢复链路。完整模型和 Windows NVIDIA 的实测范围以当前版本验收记录为准。

像素预算约束输入张量尺寸，不等于显存上限；模型权重、优化器、注意力实现及序列长度仍会影响占用。不同尺寸较多时需要更多次前向，不能据此承诺比桶训练或 NaViT 打包更快。选择较小预算可以减小单次图片前向负担，但可能增加分组次数。

旧的桶模式配置默认保持桶模式。原生变换使用独立 latent 缓存标识，避免复用曾采用缩放裁剪的桶缓存。切换模式或修改数据后应重新查看训练计划；精确断点恢复继续要求模型、数据和配置与快照一致。
