# 原生尺寸训练：保留画面与控制预算

更新：2026-09-16。原生模式按每张图自己的尺寸安排训练，不先套入公共宽高比桶。是否裁切由“图像适配方式”决定，不能把“原生”直接理解为所有像素完全不变。四个训练器的具体差异见 [训练流程与分桶对比](TRAINING_PARAMETERS.md#3-分桶选尺寸与处理图片要分开看)。本轮新增多卡路径的实现与待验范围见 [训练能力补充](TRAINING_COMPLETION_2026-09-16.md)。

## 一张图实际会变成什么

以原图 **1001×777**、对齐单位 16、预算足够为例：

| 图像适配方式 | 实际处理 |
|---|---|
| 保留完整画面（`pad`） | 图像不重新缩放；居中放进 1008×784 画布，复制边缘颜色补齐，纯补边不计直接损失。 |
| 旧裁切模式（`crop`） | 原图中心裁成 992×768；不重新缩放，但边缘少了像素。 |

新 Web 项目的配方默认 `pad`；缺少 `image_fit` 字段的旧 JSON/TOML 仍按 `crop` 读取。直接手写配置时，需要明确设置 `dataset.image_fit="pad"` 才能依赖完整画面行为。切换模型族时也保留已有几何方式，不强制迁移旧训练。

当前模型对齐单位：Anima/Krea2/Klein 为 16，SDXL 为 8。对齐由模型能力提供，不统一硬写成 16。图像、alpha 和独立 `.mask.png` 使用相同几何；`pad`/原生模式下，侧车遮罩须与 EXIF 校正后的原图尺寸一致。

## 超过预算怎么办

| 设置 | 含义 |
|---|---|
| 像素预算 | 约束单图画布，以及同一次前向分组的总像素；默认 1,048,576。补边也计入。 |
| 单边上限 | 训练画布任一边的上限；默认 4096。 |
| 超限处理 | 默认寻找能放入预算的等比缩小尺寸；也可选择明确报错，不会静默丢图。 |
| 批大小 | 逻辑批次的图片数，可包含不同尺寸。 |
| 梯度累积 | 多个逻辑批次后才更新；尾组按实际图片数归一。 |

`native + pad` 在预算内不放大、不重采样，向上对齐画布；超预算才缩小。短边小于对齐单位的图可以通过补边容纳。`native + crop` 保留旧的向下对齐和裁切，超预算后先缩小；短边小于对齐单位时会报错。

原生模式不使用公共分辨率列表、宽高比上限、桶步长或多分辨率复制；来源的重复次数仍生效。数据计划显示实际尺寸、缩小数量、逻辑批次与前向分组，不能把这些数量混作优化器步数。

## 不同宽高如何一起训练

一个逻辑批次包含 `[768×512, 768×512, 512×768]`，预算 786,432 时，前两张同尺寸且总面积符合预算，一起计算；第三张单独计算。三个样本各贡献三分之一，不会因第三张单独一组就获得更多权重。每组反向后释放计算图。

**这是按尺寸分组前向，没有实现 NaViT token 打包或专用变长注意力。** 不额外依赖某个打包内核，也不因此强制 latent 缓存。现有 Mask、VAE 编码、缓存和状态恢复可沿用。Krea2/Klein 的冻结文本编码器路径使用文字缓存；启用文本编码器训练时改为在线编码，必须另外承担编码器与反向图的显存。

## 多卡如何对齐前向次数

当前实现允许原生尺寸进入 DDP 数据并行及 FSDP 主模型全参路径，各自仍受模型、训练组件、优化器和平台限制。DDP 在每卡保留完整模型；FSDP 分担参数、梯度和优化器状态，不能用两者名称互相替代。

各卡先分到逻辑批次，再在卡内按尺寸和像素预算分组。假设同一轮 GPU 0 有三组、GPU 1 只有一组：GPU 1 会额外执行两次本卡最小分组，**这两组的损失乘零，样本计数也为零**。这样每卡以相同次序参与前向、反向和通信，避免某张卡提前停止后其他卡等待。

补齐不增加图片重复次数，也不改变真实样本的相对权重。最终 loss 和梯度按所有卡的实际图片总数归一；即使每卡分组数量或尾批大小不同，单张真实图片不会因独占一个分组而被额外加权。补齐仍运行模型，消耗算力、临时显存及可能的随机数；因此不能保证比公共桶快，也不能保证与单卡训练逐位相同。

这里有两种不同的尾部处理：

- **卡内前向分组不足**：使用上述零权重补齐，保留本轮所有已分配的真实图片。
- **整轮逻辑批次不能整除卡数**：略过最后不足一组的逻辑批次，不复制图片增加训练权重；每轮重新打乱。计划会列出首轮略过的训练项数，逻辑批次数少于卡数时直接拒绝。

计划中的 `forward_groups` 包含同步补齐的前向次数，`synchronization_groups` 单独记录其中的补齐次数；它们都不是优化器更新次数。标准有效批量为“每卡逻辑批大小 × 卡数 × 梯度累积”，不完整累积组按实际样本数处理。

精确续训仍要求相同卡数、每卡批量、梯度累积和数据身份，并恢复各卡随机状态及数据位置。改变几何方式、卡数或训练组件时，应另建任务从权重继续，不应把旧完整 state 当成可互换的配方。

## 成本与验证边界

补边仍经过 VAE 并参与模型上下文，不是免费空间；有效区权重只移除纯补边位置的直接 loss。像素预算也不是显存总上限，底模、文本编码器、优化器、注意力和预览各自需要空间。

图片尺寸种类越多，可能需要越多次前向，不能保证原生比公共桶快。原生/裁切/完整画面使用不同几何缓存身份；更换模式不能直接复用原训练的精确 state。可以创建新版本，从已有权重热启动。

已有本地检查覆盖预算/对齐、尾组样本权重、EXIF、Mask、缓存几何、恢复及小型模型调用链；新增双进程 CPU 测试覆盖原生分组、按图片数归一、非有限损失处理和恢复。本轮原生多卡的正式模型 GPU 验证仍在进行中，此处不记为通过。旧正式权重结果请按 [Windows 验收记录](WINDOWS_ACCEPTANCE_2026-09-14.md) 与 [海光验收记录](DTK_BF16_2026-09-16.md) 中实际模式、分辨率和模型理解，不把桶模式通过自动当成原生模式通过。

原生 Windows 的 DDP 任务还必须通过选定显卡上的 Gloo 启动探针；本轮没有 Windows GPU 实测，Windows FSDP 仍不开放。详见 [Windows 验证边界](WINDOWS_READINESS_2026-09-15.md)。
