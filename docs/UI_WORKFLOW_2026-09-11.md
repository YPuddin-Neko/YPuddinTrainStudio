# v0.2.0 项目工作流与 Windows 前端交付

本轮针对“新建项目只有文件夹、无法顺着界面开始训练、没有上传与模型下载、功率读数缺失”的实际使用问题改造。此前后端与小模型训练验证不等于前端已经可交付，之前 80–85% 的整体完成度估计不能作为用户流程的验收结论。

## 如何使用

1. 双击 `studio.bat` 启动 Windows 服务。浏览器左下角应显示 **v0.2.0**。
2. 点击“开始训练”或“项目”，创建项目后自动进入项目工作区。
3. **训练数据**：选择图片及同名 `.txt` 标签、整个文件夹或单个 ZIP，然后点击“上传并添加到项目”。如果文件已经在训练机上，选择“使用训练机上的文件夹”，填写例如 `D:\训练素材\角色图` 的路径。图片数量、标签数量和索引状态会在项目显示；点数据源可预览图片和编辑标签。导入的数据源自动加入本项目训练配置。
4. **模型准备**：选 Anima 或 Krea 2，分别设置主模型、文本编码器、VAE。可填写已有路径、从模型库选择，或点“下载 / 管理模型”。模型库按组件提供来源和下载表单，也支持 Hugging Face 文件 URL 或仓库加文件名。默认模型可在模型库或设置页调整。
5. **参数与启动**：编辑批大小、训练轮数、学习率、梯度累积、适配器 Rank、分辨率和触发词。下面保留完整配置、预设、TOML 导入导出。右侧显示检查结果；模型路径或数据不完整会阻止启动并列出原因。检查通过后点击“开始训练”，进入任务页查看状态、损失和产物。
6. **任务与结果**：回到同一项目查看任务记录、训练进度与生成的权重。模型和数据源各有自己的用途，项目把它们与本次参数和训练结果关联起来。

Toy 明确标为流程测试模型；它验证服务工作流，不能产出正式图像 LoRA。

## 模型与设置

- 模型库分 Anima / Krea 2，显示主模型、文本编码器、VAE 的默认准备情况。支持注册本地 safetensors 或完整文本编码器目录、切换默认、扫描目录、下载进度、取消、失败原因与重新下载。
- 标准下载来源来自对应发布者的 Hugging Face 文件页；点击“获取组件”只填写表单，点击“开始下载”才下载。下载并检查完整性、基础组件标识后才登记，完整结构兼容性仍由训练准备阶段检查。
- 下载支持完整 safetensors 单文件，不支持只下一个分片、GGUF/MXFP8 或任意网盘链接。中断任务显示失败/取消后可重新下载，尚无断点续传。私有/受限仓库使用训练机上的 Hugging Face 登录凭据。
- 设置包含每族默认模型、可选 tokenizer 目录、模型/缓存/产物目录、当前训练环境与显卡采集、服务监听、语言与主题。默认模型选择立即保存；普通设置点击保存。存储变更用于之后的任务，不自动搬迁旧文件。数据根目录仍由启动参数指定。

## 显卡功率

所有训练页面的顶栏保留“显卡功率”，仪表盘显示功率 W、驱动功率上限、利用率、温度和内存；多卡可切换顶栏显示。

Windows / Linux 服务安装包含 nvidia-ml-py。独立读取各项 NVML 数据，一个不支持的指标不会阻断其他指标；缺失时回退 nvidia-smi，并识别 Windows 常见安装路径。UUID 或唯一设备名匹配防止把逻辑 CUDA 序号当成物理显卡序号。0 W 是有效读数，不会作为缺失隐藏。

如果驱动不提供功率，显示“未提供”和原因，可进入设置检查 PyTorch、CUDA、NVML 与数据来源。CPU 版 PyTorch 下检测到的 NVIDIA 驱动卡仅供诊断，不作为可调度的 CUDA 设备。Apple MPS 不提供的功率/温度/利用率保持空值并说明；统一内存用量不冒充专用显存。

## 更新与数据保留

交付包为 `YPuddinTrainStudio-v0.2.0-2026-09-11.zip`，包含本轮源码和编译前端，不包含 Python 环境、模型权重、studio_data、用户图片、数据库与运行记录。包的解压、内容校验与服务启动验收记录在包旁同名 `.verification.json` 中，SHA-256 记录在 `.sha256` 文件中。

Windows 更新时先退出旧服务并备份，把新版包内的程序源码更新到原源码目录，保留原来的 `venv`、`studio_data` 及自定义模型/素材/产物目录。前端应以包内整个 `frontend` 目录替换旧目录，可先把旧目录移到项目目录之外备份；仅覆盖同名文件可能残留新版已删除的源码，造成内容校验不一致。然后重新运行 `studio.bat`，它会从自身所在目录启动服务。

启动脚本根据 `pyproject.toml` 内容、所选 PyTorch 构建、依赖组和系统平台计算安装签名。签名变化会尝试更新依赖；已有解释器文件和标记匹配时直接跳过，并不逐项检查依赖是否损坏，也不保证自动修复 Python 或切换到正确的 CUDA 构建。可运行 `studio.bat doctor` 查看实际环境；若已有 `venv` 的 Python 本身无法运行，启动器也不能靠这次启动自动修复它。

新前端通过源码与输出文件内容哈希校验，不依赖两台电脑的时间戳；内容校验通过的预编译前端无需 Node。若源码与前端不一致且没有 Node，会提示使用完整新版包或安装 Node 20.19+（20.x）/22.12+。如果根本没有编译前端且没有 Node，只能启动 API 服务，不能据此认为 Web 页面已可用。

这仍不是联网自更新器；不会自动获取本仓库新版本，也没有实现完整的 Python/CUDA 环境迁移。

- **真实浏览器工作流**：在隔离服务 `127.0.0.1:8876` 创建“工作流验收”项目 `p_3a52e0c4177b`；通过上传入口提交 6 个文件（3 张图片、3 个同名 `.txt`），形成受管理数据源 `d_736f5e1d5ca0`，并确认自动进入项目训练配置。
- **从页面开始训练**：选择 Toy、FP32、1 个 epoch、64 分辨率、Rank 4，页面得到 3 步计划；点击“开始训练”创建任务 `j_244b2d31cf72`。任务在本机 MPS 上完成 3/3 步，退出码为 0，并生成 epoch/final 两个权重文件，各约 19.3 KB。最终权重下载接口返回 HTTP 200，19,256 字节与磁盘文件完全相同，可读取 64 个张量。这证明本次浏览器中的上传、配置、计划、启动和结果链路接通，不代表 Anima/Krea 2 正式权重或 NVIDIA GPU 已验收。
- **模型下载**：16 项针对真实本地 HTTP 服务的下载测试通过；浏览器验证了标准来源选择和不允许域名 URL 的错误提示。本轮没有通过浏览器下载 GB 级正式模型，也没有据此确认远端 Hugging Face 下载速度或正式模型训练兼容性。
- **显卡采集**：NVML / nvidia-smi 回退、独立指标、有效 0 值和设备映射由 6 项单元测试验证。本机没有完成远端 Windows 的实际 NVIDIA 驱动、功率读数或 CUDA 训练验收。
