## 判定标准和环境

使用实际模型和用户提供的 16 张训练图片及原始 TXT：连续训练 8 步，与训练至第 4 步保存完整状态、退出工作进程、由新进程恢复至第 8 步对比。全部训练权重、优化器、调度器、随机数状态、采样位置、训练进度及预览 PNG 必须逐位一致。数值误差仅用于诊断，不作为放行阈值。

新海光节点为两张 BW 64 GiB，DTK 26.04，厂商 PyTorch `2.7.1+das.opt1.dtk2604`，HIP `6.3.26093`。原节点已到期；本轮更换了训练图片，不能将旧节点结果混记为同一数据集复验。32 个原始输入文件逐一核对 SHA256，验收不会改写它们。大模型直接在远端从 ModelScope 下载并核验散列，不再从本机传输模型。

正式源码在独立目录启用：836 个跟踪文件、157 个产品 Python 文件逐一匹配；产品 Python 清单 SHA256 为 `5a5b1ecd60737e3589829019b50a690b8e5a3d989e93e9773312481a394f0929`。原服务、原源码基线、模型和训练数据保留。

Krea2 确实分片了全部 12,820,073,036 个参数：33 个 FSDP 组，FP32 主参数全局占 51,280,292,144 字节，每张卡保存其中的一半，没有复制的主参数。前向使用 BF16，梯度归约使用 FP32。候选峰值张量分配每卡约 54.45 GiB；这不是把两卡显存视作无需通信的统一显存，也不是双倍速度的测试结论。

本轮均为 512 分辨率、全局批大小 2、冻结文本编码器。Krea2 使用无一阶动量的 HF Adafactor，SDXL 使用 AdamW；全参开启逐块梯度检查点，适配器关闭梯度检查点。Krea2 的双卡容量结果不代表同样显存能容纳 AdamW 的额外完整优化器状态。

Anima 全参的 BF16 前向、FP32 线性层反向候选仍有 685 个权重张量差异。该用例原比较进程因 CPU 线程过多而终止，随后用原比较函数、4 个 CPU 线程独立完成比较，仍判定失败；不能把补充比较说成原驱动完整执行成功。

Anima 适配器的“仅线性层反向 FP32”候选也未通过：840 个张量不同，报告 SHA256 为 `c72400af065faa3bb9bac4911a00e917e5cc4091da20da15efce684f790aeb35`。随机数、采样和调度器状态相同，优化器、进度和预览不同。

后续 Anima LoKr 联合线性层与 LoKr 反向 FP32 仍未通过，840 个张量不同，原报告 SHA256 为 `12f429bfb8bbe9f69f0baa7cec586ff1123a5fc2c99c6e657ed85006b82e2888`。这些失败均保留，不能用误差较小代替严格通过。

基于固定产品源码 `4477bad` 的 SDXL 双卡独立候选也已完成：DDP LoKr 的 2100 个张量及 FSDP 全参的 1680 个张量均逐位一致，五类状态、PNG、两 rank 的计算合同及原资产检查通过。DDP 报告 SHA256 为 `91ce405e02f15a0cf3a1e69583cc2e272959b6ef635adb90bc67f88bc748bfd0`；FSDP 报告为 `62a0cad097655642679ae3caa04f289e654fb7e3ff2ba034968fc5ec51e6c994`。FSDP 使用 389 个包装模块、383 个非空参数组，每卡主参数 5,134,927,368 字节，最高张量峰值约 24.33 GiB。两项属于外部候选，接入后的产品入口仍需单独复验。

带张量复制、散列和同步的 Anima 追踪实验曾全部一致，但未插桩训练仍失败。因此追踪结果仅帮助排除状态来源差异，不能作为续训修复依据。另已证实两个相关实验的第 4 步权重、优化器、随机数、调度器和采样状态数值完全相同。

## 产品行为与复验

产品保留用户原始配置，由规划器与训练器共用的解析器选择实际精度；恢复训练会核对保存的计算策略，不能将旧策略状态自动迁移为新策略。

- Krea2：可复现训练、主干全参、不训练文本编码器、双卡及以上 FSDP、请求 BF16 时，使用 `dtk-krea2-fsdp-bf16-linear-fp32-backward-v1`。
- SDXL：同样的确定性条件下，单卡主干全参，或 FP32 参数、非量化底模、无 DoRA 的 LoKr bypass，使用 `dtk-sdxl-bf16-conv-fp32-linear-backward-v1`。
- 两项都关闭 TF32，使用数学 SDPA。其余已支持的全参组合仍按原 FP32 策略处理，不能将这些组合写成 BF16 已通过。
- 界面显示实际生效的 BF16/FP32 分工。关闭可复现训练后恢复用户原始选择。

本次扩展让 SDXL LoKr 数据并行沿用原卷积/线性层策略，并给 SDXL FSDP 全参单独记录 `dtk-sdxl-fsdp-bf16-conv-fp32-linear-backward-v1`。FSDP 先按 BF16 汇集参数，再进行 FP32 卷积，与直接读取未分片 FP32 主参数存在不同舍入边界，因此拒绝混用两种策略的完整训练状态。新产品入口复验尚待完成；目前实机数值证据仅覆盖两卡及上文固定配方。

新增真实双进程 CPU FSDP 回归覆盖 Conv+Linear/AdamW 和 Linear/Adafactor：验证实际卷积前后向 FP32、BF16 参数汇集、FP32 梯度、状态恢复精确一致和错误策略在加载前被拒绝。该测试发现并修复了分片后 `FSDPConv2d` 被普通类型检查误拒绝的问题，仍不接受任意 Conv2d 子类。

Krea2 正式产品双卡复验已严格通过：430 个权重张量、五类状态和预览 PNG 全部逐位一致，两阶段各 17 项执行与产品策略检查通过，所有所属进程正常退出，原资产未变。原报告 SHA256 为 `24ee065113d497ee7d205d8a8b728854a7e08fb38c9332173545155bb390a69e`。两阶段整段耗时约 720.22 / 721.70 秒，包含加载、保存和导出，不是纯训练吞吐。SDXL LoKr 正式产品入口随后通过：2100 个权重张量、五类状态和预览图全部一致；原有 15 项门禁和新增 4 项产品入口检查在两阶段均通过。报告 SHA256 为 `317a11195903e00061d1bec5601ec72cb46c049a5edd17c11a566ab903f26b56`。SDXL 全参正式入口也已通过：1680 个张量、五类状态和 PNG 全等，原 18 项全参门禁及产品检查通过。报告 SHA256 为 `a68408b9f6a18add494b8e5031d92587433b351a868bf5d3bb11ba338c8a1a83`。两张卡随后用于 Anima 的后续候选与定位测试。首次 Krea2 外部验收脚本因安全导入路径遗漏，在 GPU 初始化前退出；修正并完成真实环境 CLI/产品导入预检后重新启动，产品源码未变。
